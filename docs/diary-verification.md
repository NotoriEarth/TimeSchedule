# PC 다이어리 확인 절차

이 문서는 새 다이어리의 수동 확인 절차다. 아래 항목은 절차이며, 수행 결과는 PR과 실행 보고서에 별도로 기록한다.

1. 기존 앱을 트레이에서 완전 종료한 뒤 새 실행 파일을 연다. 기존 일정과 메모가 남아 있는지 확인한다.
2. 상세 창의 월간 달력에서 날짜를 눌러 해당 날짜의 일정을 추가한다.
   - 일정·기록 편집창 바깥을 클릭하면 변경이 없는 창은 닫혀야 한다. 작성 중이면 저장하지 않고 닫을지 묻고, **계속 편집**을 누르면 내용이 그대로 남아야 한다. **저장하지 않고 닫기**를 선택해야 작성 내용을 버리고 닫힌다.
3. 일요일 앞 주간 버튼을 가리켜 다음 월요일부터 다음 일요일까지 강조되는지 확인한다. 2026년 10월 25일 앞 버튼은 10월 26일~11월 1일을 연다.
4. 주간 화면에서 기록을 여러 개 작성하고 제목을 눌러 상세를 펼친다. 월간으로 돌아가면 원래 보던 월이 유지되어야 한다.
   - 첨부한 종이 다이어리처럼 윗줄은 주간 정보·월·화·수, 아랫줄은 목·금·토·일의 4열×2행이어야 한다.
   - 기록이 많은 날짜 또는 긴 본문을 펼친 날짜 안에서 스크롤한다. 날짜 제목과 추가 버튼은 남고, 다른 날짜 칸의 높이와 스크롤 위치는 바뀌지 않아야 한다.
5. 프로젝트를 만들고 자유 노트와 트러블슈팅 기록을 작성한다. 앱을 다시 열어 작성한 내용이 유지되는지 확인한다.
6. 프로젝트에 로컬 Git 저장소 경로를 지정하고 커밋을 가져온다. 같은 저장소를 다시 가져와도 중복되지 않아야 한다. 가져온 기록을 수정한 뒤 재수집해도 수정 내용이 유지되어야 한다.
7. 제목과 본문에 한국어 검색어를 넣고 검색한다. 결과를 열면 해당 일정·노트·프로젝트·개발 기록을 확인할 수 있어야 한다.
8. 주간/프로젝트 요약 초안을 생성하고 수정해 저장한다. 새 초안 생성이 기존 자유 노트를 덮어쓰지 않는지 확인한다.
9. 상세 창을 닫아도 바탕화면 달력과 트레이가 남는지 확인한다. 위젯 날짜로 상세 창을 다시 연다.

## 검증 구분

- 브라우저 미리보기는 브라우저 저장소를 사용하며 네이티브 SQLite 검증을 대신하지 않는다.
- Git 실행과 Windows 바탕화면 연결은 네이티브 전용이다.
- 외부 AI, ChatGPT 학습 진도, Space 연결 및 기기 간 동기화는 이 버전에서 연결 완료로 표시하지 않는다.
- 요약은 구현된 생성 방식과 출처를 화면에 명시하며, 근거 없는 성과 수치를 생성하지 않는다.

## 2026-10-29 개발 검증 결과

- Rust 단위 테스트 21개와 Windows 네이티브 통합 테스트 1개 통과(건너뜀 없음). 기존 v1 데이터 이전, 한국어 검색·인덱스 갱신, 저장 유지, 실제 임시 Git 저장소 수집, 중복 방지, 사용자 수정 보존, 원문 길이 초과 시 원자적 거부를 포함한다.
- 날짜·근거 초안 Node 테스트 3개 통과. 월/연도 경계의 월요일~일요일 범위와 윤일, 초안의 출처 및 원문 불변성을 확인했다.
- 브라우저 미리보기에서 10월 26일~11월 1일 주간 열기, 10월 월간 복귀, 11월 1일 클릭 시 해당 날짜 일정 편집창, 기록 작성·펼치기·출처 링크 표시, 한국어 본문 검색과 결과 편집창, 새로고침 후 저장 유지, 프로젝트·자유 노트 생성, 별도 근거 초안 저장을 확인했다.
- 독립 코드 검토 후 프로젝트 이동에 따른 커밋 중복, 긴 커밋 원문 잘림, 비동기 초안이 다른 편집창을 덮어쓰는 문제를 보완했다.
- Svelte/TypeScript 검사 0 오류·0 경고, 프런트엔드 및 Windows x64 릴리스 빌드, Rust 포맷 검사 통과. 실행 파일 `artifacts/TimeSchedule-diary.exe` 크기 7,803,904바이트.
- 별도 `.test-data/diary-release-smoke` 폴더로 릴리스 실행을 확인했다. 프로세스 응답, 데이터 파일 생성, 로그의 main ready 및 바탕화면 부모 연결·불투명도 82% 적용을 확인했다. 테스트 프로세스만 종료했으며 기존 앱과 사용자 데이터는 건드리지 않았다. 네이티브 화면 자동화는 창 최소화 상태 오류로 진행하지 못했다.
- 브라우저 검증은 네이티브 창의 실제 클릭·트레이 동작·기존 사용자 DB 검증을 대신하지 않는다. 해당 항목은 위 절차대로 사용자가 확인해야 한다.

이번 버전은 수동 Git 수집과 로컬 근거 정리 초안을 제공한다. 자동 수집, 외부 AI, ChatGPT/Space, 기기 간 동기화 및 Rust UI 이식의 메모리 비교는 후속 범위다.

## 주간 펼침면 수정 검증

첨부 이미지 기준으로 4열×2행과 모눈 배경을 적용했다. 1280×720 및 앱 최소 크기 800×620 브라우저 화면에서 7일 모두 한 화면에 들어오고 페이지 가로·세로 넘침이 없는 것을 확인했다. 긴 목요일 기록을 펼쳤을 때 칸 높이를 유지하고, PageDown으로 목요일 기록 영역만 스크롤되며 나머지 6일과 전체 페이지의 스크롤 위치는 0을 유지했다. 날짜 제목과 추가 버튼은 스크롤 영역 밖에 고정한다. 이 확인은 브라우저 검증이며 네이티브 창에서의 실제 조작은 사용자 확인이 필요하다.

수정 후 Svelte 검사 0 오류·0 경고, Node 테스트 3개 및 Windows 릴리스 빌드가 통과했다. 최신 확인용 파일은 `artifacts/TimeSchedule-diary-weekly.exe`이다. 이전 실행 파일은 보존했다.

## 편집창 바깥 클릭 검증

브라우저에서 빈 일정창의 바깥 클릭 닫기, 작성 중인 일정·기록의 저장 안 함 확인, **계속 편집** 시 내용 보존, 명시적으로 **저장하지 않고 닫기**를 선택한 뒤 닫힘을 확인했다. 긴 편집창에서도 확인 영역이 보이도록 스크롤하고 **계속 편집** 버튼으로 포커스를 옮긴다. 창 내부 클릭 및 본문 안에서 바깥으로 드래그하는 동작은 닫기를 실행하지 않는 것을 확인했다. 저장 중에는 기존과 같이 닫기 동작을 무시한다.

수정 후 Svelte 검사 0 오류·0 경고와 Windows 릴리스 빌드가 통과했다. 최신 확인용 파일은 `artifacts/TimeSchedule-diary-dialog.exe`이며 이전 파일들을 보존했다. 빈 기록창의 바깥 클릭 닫기도 확인했다. 네이티브 창에서의 실제 클릭 검증은 사용자 확인 항목이다.

## 별도 미저장 확인 팝업

미저장 확인은 편집창 안쪽 안내 대신 화면 중앙의 별도 모달 팝업으로 변경했다. 팝업 뒤의 편집창은 조작할 수 없고, **계속 편집**이 기본 포커스다. **계속 편집** 또는 Esc는 확인 팝업만 닫고 원래 편집창의 내용·스크롤 위치를 보존한다. 팝업 바깥 클릭으로 내용을 버리지 않으며 **저장하지 않고 닫기**를 명시적으로 눌러야 편집창까지 닫힌다. 이 흐름과 팝업 중앙 배치를 브라우저에서 확인했다. 기존 항목 삭제 확인은 이번 변경 대상이 아니다.

일정·기록 양쪽의 팝업과 명시적 버리기, 변경 없는 창 닫기까지 확인했고 브라우저 콘솔 오류가 없었다. Svelte 검사 0 오류·0 경고와 Windows 릴리스 빌드 통과. 최신 확인용 파일은 `artifacts/TimeSchedule-diary-popup.exe`이며 이전 실행 파일들을 보존했다. 네이티브 창의 실제 조작은 사용자 확인 항목이다.
