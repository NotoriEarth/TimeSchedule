# 다이어리 연월 이동·날짜 더블클릭·팝업 위치·공통 일정 폼

2026-10-31, `codex/widget-customization`, PR #6의 후속 수정이다. 사용자는 다이어리에 연·월 클릭 이동을 추가하고 위젯/다이어리 일정 추가창의 양식도 통일하도록 요청했다.

## 적용

- 다이어리 월간 화면에서도 상단 **년 / 월**을 눌러 같은 연월 입력창을 연다. 누른 항목을 선택하며 날짜 직접 입력도 가능하다. 다이어리에서 이동하면 다이어리의 날짜만, 위젯에서 이동하면 위젯의 날짜만 바뀐다.
- 다이어리 월간·주간 날짜에서 한 번 클릭하면 선택하고, 두 번 클릭하면 해당 날짜의 **새 일정**을 추가한다. 주간 일정 카드의 상세 보기와 버튼은 날짜 더블클릭으로 처리하지 않는다.
- 위젯 일정창과 두 화면의 연월 이동창은 **열었던 창의 실제 화면상 영역 중앙**에 배치한 뒤 표시한다. 이미 열린 연월창도 원본 창을 옮긴 후 다시 누르면 새 위치에 맞춘다. 화면 가장자리에서는 같은 모니터의 작업 영역 안으로 보정한다.
- 다이어리 일정 편집은 기존처럼 다이어리 내부 중앙 모달이다. 위젯의 별도 일정창도 같은 `Editor/Form`, 입력항목, **공통 패널 템플릿**을 사용한다. 패널 기본 크기 650×560, 여백22, 본문 높이220, 배경·버튼·확인 양식이 같다. 좁은 창은 필드 영역을 스크롤하고 저장/취소 버튼을 유지한다.
- 기존 초안, 한글 조합 중 닫기 보호, 미저장 확인을 유지한다. DB 변경은 없다.

## 확인한 내용

- `cargo test --workspace --locked --offline`: **90개 통과, 의도된 제외2개**.
- 실제 Iced 트리: 다이어리/위젯 연월 버튼의 올바른 대상, 월간/주간 단일·이중 클릭, 하위 일정 버튼 구분, 두 폼의 제목·본문 크기/상대 위치 일치.
- Windows 소유 테스트 창: 자식 원본의 화면 좌표 `(230,150)`에서 팝업 `(330,250)`, 최상위 다이어리 원본에서 `(500,350)` 배치. 크기는 유지한다. 다른 스레드/잘못된 HWND/자식 대상 변경 거부. 음수 화면 좌표와 가장자리 보정은 별도 계산 테스트로 확인했다.
- 늦게 도착하거나 닫힌 팝업의 결과 무시, 원본 창이 없어졌을 때 숨겨진 창이 영구히 남지 않는 처리, 배치 전 포커스가 창을 먼저 표시하지 않는 처리.
- 다이어리와 위젯의 공통 폼, 좁은 창, 확인창, 다이어리 연월 제목과 이동창을 실제 렌더러 PNG로 생성·확인했다. PNG는 바탕화면 캡처가 아니다.
- 독립 검토에서 재사용 연월창 위치와 별도로 남아 있던 위젯 본문 높이를 발견해 회귀 테스트로 재현한 후 수정했다.

실제 마우스 클릭, Windows 전경 포커스/전체 선택, 한글 IME, 여러 모니터의 서로 다른 DPI 전환은 수동 확인 항목이다. 테스트 창의 검증을 사용자 환경에서의 조작 성공으로 표현하지 않는다. 기존 실행 중인 사용자 앱은 종료하지 않는다.

## 직접 확인

1. 기존 앱을 트레이에서 완전히 종료하고 아래 새 실행 파일을 실행한다.
2. 다이어리 상단 년/월을 각각 눌러 값을 바꾸고, 취소·Esc도 확인한다.
3. 월간·주간 날짜를 한 번/두 번 클릭해 날짜 선택과 새 일정 추가가 구분되는지 확인한다.
4. 다이어리와 위젯을 화면의 서로 다른 위치로 옮긴 후 각각 연월창을 연다. 위젯의 일정창도 위젯 중앙에 떠야 한다. 열린 연월창을 둔 채 원본 창을 옮기고 다시 눌러 재배치도 확인한다.
5. 위젯과 다이어리에서 일정 추가/수정을 열어 입력항목·여백·본문·버튼이 같은지 확인한다. 내용을 입력하고 닫을 때 미저장 확인과 한글 입력 보호도 확인한다.
6. 작은 창과 화면 가장자리, 가능하면 다른 DPI의 보조 모니터에서도 저장/취소와 창 제목이 접근 가능한지 확인한다.

로그와 PNG: 로컬 `artifacts/diary-navigation/`. 실행 파일과 테스트 데이터는 Git에 포함하지 않는다. 사용자 확인 후 명시적인 승인 전까지 머지하지 않는다.
