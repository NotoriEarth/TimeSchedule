# 0.11.3 카테고리·공통 날짜 항목 검증

## 0.11.3 후속 수정: 새 카테고리 추가 버튼

사용자가 새 카테고리가 추가되지 않는다고 보고했다. 실제 앱 모달에서 이름·색상을 입력한 상태로 `+ 추가`를 클릭하면 저장소에 항목이 생기지 않고 초안만 빈 문자열로 바뀌는 실패를 재현했다. 같은 입력에서 아래 `저장` 클릭은 통과했다. 추가 버튼이 저장 대신 새 초안 초기화 액션에 연결된 것이 원인이었다. 기존 테스트는 저장 액션을 직접 호출해 버튼의 잘못된 연결을 발견하지 못했다.

새 입력 상태의 `+ 추가`를 기존 저장 경로에 연결했다. 수정 중 새 초안으로 전환하는 버튼은 `새로 작성`으로 구분하고 오류도 초기화한다. 버튼을 저장·로딩 중 비활성화하며, 빈 이름·중복 이름으로 실패하면 초안을 유지한다. DB·드래그·동기화·타이머는 변경하지 않는다.

실제 800×620 앱 모달의 버튼 위치에서 press/release를 보내고 실제 worker/SQLite 저장 결과를 확인하는 회귀를 추가했다. 새 분류 추가와 선택 색상, 중복 거절·초안 보존, 기존 저장 버튼, 기존 ID 수정, 새 초안 전환·빈 이름 오류·그 뒤 정상 추가를 확인한다. 사용자 환경에서 실제 키보드·마우스로 입력한 결과는 사용자 확인 대상이다.

`cargo test --workspace --locked --offline`: 182개 통과, 수동 검증 등 7개 기본 제외. 이번에 실제 모달 버튼 회귀 3개를 추가했다. 독립 검토에서는 수정 필요 사항을 발견하지 않았고, 실제 Windows 조작과 배포 EXE 실행은 검토 범위 밖으로 구분했다.

## 0.11.2 후속 수정: 카테고리 드래그 애니메이션

사용자가 승인한 2안에 따라 잡은 행은 마우스를 즉시 따라오고, 주변 행과 놓은 행에만 150ms EaseOutCubic 이동을 적용했다. 고정된 행 중심으로 삽입 위치를 판단하고 ID별 위젯 상태를 유지해 빠른 방향 전환이나 정착 중 재드래그에도 대상이 바뀌지 않는다. 행 내부 배치를 다시 만들지 않고 이미 계산한 배치를 이동하며, 모션 또는 가장자리 자동 스크롤이 있을 때만 다음 프레임을 요청한다. 기존 Iced API를 사용하고 새 의존성·주기 구독·프로세스를 추가하지 않는다.

- 변경 전 실제 Iced 이벤트 테스트에서 손잡이를 위로 20px 이동해도 글자 위치가 168.29999px에 그대로 남는 실패를 확인했다. 변경 후 같은 테스트에서 즉시 20px 따라오고 저장소 순서는 아직 바뀌지 않음을 확인했다.
- `cargo test --workspace --locked --offline`: 최종 전체 179개 통과, 수동 검증 등 7개 기본 제외. 새 자동 회귀 8개를 추가했으며, 별도 `render_category_drag_motion_previews --ignored` 1개도 통과했다.
- 실제 retained tree에서 75ms 중간 위치와 150ms 정착, 빠른 방향 전환·연속 드래그, 중복 release의 단일 저장, 4px 미만 클릭, Esc·창 포커스 상실·창 밖 이동·목록 밖 release 취소를 검증했다.
- 실제 scrollable 안에서 휠 및 가장자리 자동 스크롤 뒤의 대상 정합성, 외부 목록 변경 시 취소, ↑/↓ 이동과 저장 실패 시 원위치 복귀, 동작 종료 뒤 `RedrawRequest::Wait`를 검증했다. 실제 앱/DB 테스트에서 오래된 순서 저장을 거절하고 편집 초안·외부 추가 항목을 보존한다.
- 독립 검토의 중요 지적 2개를 실패 테스트로 확인하고 보완했다. 정착 중 다시 누른 행이 75ms 동안 15→52.625px로 흘러가던 동작은 누른 위치에서 멈추며, 문턱 미달 놓기·취소도 그 위치에서 복귀한다. 외부 카테고리 추가 후 순서 저장 충돌은 초안·오류를 보존한 채 최신 목록을 한 번 읽어 다음 사용자 재시도가 성공하도록 했다. 수정 후 각 회귀와 전체 suite를 통과했다. 자동 재저장은 하지 않는다.
- 합성 카테고리 3개로 실제 앱 모달을 800×620/1160×820에서 초기·누름·이동·75ms·놓기·150ms의 12개 PNG로 렌더링했다. `.cache/category-motion-previews/`의 작은 화면 이동·중간·정착과 기본 크기 화면을 확인했다.
- 사용자 확인: 다이어리 상단 카테고리의 ⠿ 손잡이를 천천히/빠르게 끌어 주변 행이 비켜나고 놓을 때 정착하는지, Esc로 순서가 복구되는지 확인한다. 저장 뒤 위젯·다이어리의 같은 날짜에서 표시 우선순위를 확인한다. 긴 목록은 끝으로 끌어 자동 스크롤도 확인한다.

마우스 기반의 합성 이벤트·네이티브 렌더링 검증이며 실제 손 조작의 체감, Windows 표시 지연, 터치·펜 조작은 검증하지 않았다. 아래 0.11.0 자원 측정은 이번 애니메이션의 자원 측정 결과가 아니다.

`scripts/build-native.ps1 -Offline`의 최종 네이티브 테스트 120개와 0.11.2 release 빌드는 통과했다. 실행 중에는 교체를 중단했고 사용자 저장·완전 종료 확인 후 `artifacts/TimeSchedule.exe`를 교체했다. 8,835,072 bytes로 0.11.1보다 50KiB 증가했으며 최종 SHA-256은 `FD3E1A941B9F70A648CDB23207CBC5F6AF8144E7A7204E0D82ABC40AF8B5FC09`다. 대표 파일과 release 출력의 해시 일치를 확인했다. 이전 0.11.1은 `artifacts/archive/TimeSchedule-20261103-173141-9da5df00a6164704b1f8daa15304e8ca.exe`에 보관했다. 사용자 앱은 자동 실행하지 않았다.

## 0.11.1 후속 수정: 날짜 칸 맨 아래 더보기

사용자가 위젯과 다이어리, 특히 다이어리에서 제목 대신 `+3개 더`가 먼저 보인다고 보고했다. 기존 코드에도 공간 계산은 있었지만 더보기 공간을 고정 18px로 예약하고 버튼을 목록 바로 뒤에 배치했다. 글자 크기 11px, 내용 영역 52px에서 실제 두 줄 기록 36.6px와 버튼 14.3px는 함께 들어가는데 기존 예약값 때문에 기록이 전부 숨겨졌다. 실제 Iced 레이아웃 테스트에서 제목 없이 `+3개 더`만 나오는 실패를 확인했다. 160px 영역에서도 버튼 아래에 35.9px가 비는 별도 실패를 재현했다.

더보기 예약과 실제 버튼 높이를 동일한 글자 높이로 계산하고, 날짜 칸의 남은 공간을 사용해 버튼을 아래에 배치했다. 제목과 프로젝트명 두 줄은 통째로 표시한다. 모든 항목이 들어가면 더보기는 없고 완료 항목은 기존처럼 접는다. 조회·저장·동기화·타이머나 의존성은 추가하지 않았다.

- `cargo test --workspace --locked --offline`: 171개 통과, 수동 검증용 등 6개 기본 제외. 기존 0.11.0의 167개에 회귀 테스트 4개를 추가했다.
- 실제 Iced 레이아웃에서 52px 영역, 아래쪽 버튼 위치, 공간 증가 시 더보기 제거, 기본 다이어리 1160×820 및 위젯 960×640, 24px 큰 글꼴의 범위 안 배치를 확인했다.
- `render_calendar_overflow_previews --ignored`: 기본/높은 다이어리와 위젯 4개 합성 화면을 렌더링해 확인했다. 기본 크기에서 기록 1개와 `+2개 더`, 높이를 늘리면 기록 3개와 더보기 제거를 확인했다. 결과는 `.cache/calendar-overflow-previews/`에 있다.
- 기존 날짜당 최대 16개 머리말 조회는 유지한다. 실제 사용자 데이터·물리 모니터·마우스 체감은 사용자가 실행 파일에서 확인한다. 아래 0.11.0 자원 측정은 0.11.1 재측정 결과가 아니다.
- 독립 검토에서 수정 필수 사항은 없었다. 기존 16개 조회 한계, 좁은 칸의 제목 생략·더보기 글꼴/색상은 이번 높이 수정에서 변경하지 않았다. 실제 데스크톱 클릭·연속 크기 조절·DPI별 사용감은 정적 검증과 구분한다.

사용자 확인: 같은 날짜에 기록을 3개 둔 뒤 다이어리와 위젯에서 프로젝트명·작업명이 먼저 보이고, 남은 개수는 날짜 칸 맨 아래에 나타나는지 확인한다. 창 높이를 늘리면 표시 항목이 늘고, 모두 들어가면 더보기가 없어야 한다. 버튼을 눌러 남은 항목 상세도 확인한다.

`scripts/build-native.ps1 -Offline`로 0.11.1을 빌드하고, 사용자 종료 확인 후 `artifacts/TimeSchedule.exe`를 교체했다. 이전 0.11.0은 `artifacts/archive/`에 보관했다. 새 EXE는 8,783,872 bytes, SHA-256 `CBFE16742206871DCE1BDF916904905A68F1024F549746716DC069A9A74AECF2`다. 앱을 강제 종료하거나 자동 실행하지 않았다. PR #14는 사용자 테스트 승인 전까지 미병합 상태로 둔다.

## 변경과 원인

위젯과 다이어리는 이미 같은 SQLite 파일을 사용했다. 그러나 위젯 날짜 조회와 빠른 입력창은 일정만 다뤘고, 다이어리 월간 칸도 기록 제목 대신 개수만 표시했다. 기록 누락은 별도 저장소 간 복사 실패가 아니라 조회·표시 범위 문제였다. 실제 Iced 렌더링 테스트에서 누락을 재현한 뒤 공통 날짜 항목 조회로 교체했다.

기존 event/task/entry ID를 유지한다. 일정·기록·새 카테고리를 같은 날짜와 표시 순서로 읽고, 저장·날짜 이동·완료·삭제 후 두 범위와 열린 날짜 목록을 갱신한다. 위젯과 앱이 다른 달을 보고 있다면 그 날짜 범위는 독립적으로 유지한다. 작성 중인 초안은 보존하며 오래된 수정은 거절한다.

새 카테고리는 기록형 입력이다. 시간·완료는 기본 일정 카테고리에서 사용한다. 기록 원래 제목과 프로젝트 이름은 보존하고 선택적인 표시 별칭만 달력에 적용한다. 카테고리 삭제, 반복 일정·알림·Google Calendar 동기화, 서버/기기 간 동기화는 이번 기능에 포함되지 않는다.

- 실제 SQLite: 카테고리 추가/순서/재시작 보존, 잘못된 색상·오래된 재정렬 거절, 205개 기록의 집계·페이지, 완료 목록 독립 조회, 기존 할일 내용·시간·검색, 원자적 편집과 충돌 보존, 프로젝트 별칭, 스키마 3 백업·이전.
- 실제 Iced worker 비동기 경로: 위젯에서 기록 작성, 다이어리에서 원문 조회·수정·날짜 이동, 위젯에서 삭제, 일정 완료 후 두 화면 갱신. 드래그 중 DB 무변경·놓을 때 저장.
- 실제 Iced 레이아웃/렌더러: 두 화면에 프로젝트명·작업명 표시, 항목 클릭·완료 체크가 날짜 더블클릭으로 전파되지 않음, 작은 창·기존 설정 스크롤 회귀. 두 테마와 800×620/1160×820 앱, 960×640 위젯과 350×330 날짜 팝업, 800×620 주간 화면의 긴 제목을 확인했다. 100/150/200% 렌더러 배율은 합성 검증이며 실제 모니터 전환 확인과 구분한다.
- 새 폴링·상주 프로세스·AI 호출은 없다. 날짜별 최대 16개 머리말과 정확한 전체 개수, 50개 페이지를 사용하며 본문은 열 때 조회한다. 기존 설정 렌더러 경로를 유지한다.

## 사용자가 확인할 순서

1. `artifacts/TimeSchedule.exe`에서 버전 0.11.0 확인. 다이어리와 위젯을 같은 날짜로 맞춘다.
2. 다이어리 상단 `카테고리`에서 새 분류를 추가하고 색상을 고른다. 손잡이를 드래그해 기록/일정과 순서를 바꾼다.
3. 다이어리에서 `+ 기록`을 눌러 프로젝트·카테고리·제목·내용을 저장한다. 위젯에서 같은 항목을 누르면 원문이 열려야 한다. 공간이 부족하면 `+N개 더`에서 확인한다.
4. 위젯 날짜를 더블클릭해 기록을 작성한다. 다이어리에서 같은 항목을 수정하고 날짜를 옮긴 후 양쪽에서 확인한다. 삭제도 양쪽에 반영되어야 한다.
5. 일정을 완료 처리한 후 `완료 N개`를 펼쳐 확인한다. 기본 일정 입력에서 제목 아래 내용·종일/시간·완료를 확인한다.
6. 긴 프로젝트 이름은 프로젝트 수정의 짧은 표시 이름, 긴 기록 제목은 기록 수정의 짧은 작업명을 설정한다. 원문 상세의 원래 제목은 유지되어야 한다.
7. 기존 설정 휠 스크롤, 위젯 이동·크기 변경, 글꼴/테마를 확인한다.

사용자 데이터와 실제 다중 모니터·배율 전환, 손으로 드래그할 때의 체감은 사용자 확인 대상이다. 자동 테스트와 합성 화면 검증이 PR 머지 승인을 대신하지 않는다.

## 실행 파일과 짧은 자원 비교

최종 소스 `d944d69`로 빌드한 네이티브 0.11.0은 8,784,384 bytes이며 SHA-256은 `4D36D443AD39A70BE522C414096983E239A15F72A03259D06D0FE870774EE9D0`이다. 대표 경로는 `artifacts/TimeSchedule.exe`이고 교체 시 이전 EXE를 `artifacts/archive/`에 보관한다.
