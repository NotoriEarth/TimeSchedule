# 0.11.0 카테고리·공통 날짜 항목 검증

## 변경과 원인

위젯과 다이어리는 이미 같은 SQLite 파일을 사용했다. 그러나 위젯 날짜 조회와 빠른 입력창은 일정만 다뤘고, 다이어리 월간 칸도 기록 제목 대신 개수만 표시했다. 기록 누락은 별도 저장소 간 복사 실패가 아니라 조회·표시 범위 문제였다. 실제 Iced 렌더링 테스트에서 누락을 재현한 뒤 공통 날짜 항목 조회로 교체했다.

기존 event/task/entry ID를 유지한다. 일정·기록·새 카테고리를 같은 날짜와 표시 순서로 읽고, 저장·날짜 이동·완료·삭제 후 두 범위와 열린 날짜 목록을 갱신한다. 위젯과 앱이 다른 달을 보고 있다면 그 날짜 범위는 독립적으로 유지한다. 작성 중인 초안은 보존하며 오래된 수정은 거절한다.

새 카테고리는 기록형 입력이다. 시간·완료는 기본 일정 카테고리에서 사용한다. 기록 원래 제목과 프로젝트 이름은 보존하고 선택적인 표시 별칭만 달력에 적용한다. 카테고리 삭제, 반복 일정·알림·Google Calendar 동기화, 서버/기기 간 동기화는 이번 기능에 포함되지 않는다.

## 확인한 검증

2026-11-03: Rust 전체 164개 통과(5개는 수동/자식 프로세스 검증으로 기본 제외), Node 33개 통과. 추가 수동 native 미리보기 테스트 1개 통과. git diff --check 통과. 실행 파일과 자원 측정은 최종 전달 시 갱신한다.

- 실제 SQLite: 카테고리 추가/순서/재시작 보존, 잘못된 색상·오래된 재정렬 거절, 205개 기록의 집계·페이지, 완료 목록 독립 조회, 기존 할일 내용·시간·검색, 원자적 편집과 충돌 보존, 프로젝트 별칭, 스키마 3 백업·이전.
- 실제 Iced worker 비동기 경로: 위젯에서 기록 작성, 다이어리에서 원문 조회·수정·날짜 이동, 위젯에서 삭제, 일정 완료 후 두 화면 갱신. 드래그 중 DB 무변경·놓을 때 저장.
- 실제 Iced 레이아웃/렌더러: 두 화면에 프로젝트명·작업명 표시, 항목 클릭·완료 체크가 날짜 더블클릭으로 전파되지 않음, 작은 창·기존 설정 스크롤 회귀. 두 테마와 800×620/1160×820 앱, 960×640 위젯 미리보기 확인.
- 새 폴링·상주 프로세스·AI 호출은 없다. 날짜별 최대 16개 머리말과 정확한 전체 개수, 50개 페이지를 사용하며 본문은 열 때 조회한다. 기존 설정 렌더러 경로를 유지한다.

## 사용자가 확인할 순서

1. `artifacts/TimeSchedule.exe`에서 버전 0.11.0 확인. 다이어리와 위젯을 같은 날짜로 맞춘다.
2. 다이어리 상단 `카테고리`에서 새 분류를 추가하고 색상을 고른다. 손잡이를 드래그해 기록/일정과 순서를 바꾼다.
3. 다이어리에서 `+ 기록`을 눌러 프로젝트·카테고리·제목·내용을 저장한다. 위젯에서 같은 항목을 누르면 원문이 열려야 한다. 공간이 부족하면 `+N개 더`에서 확인한다.
4. 위젯 날짜를 더블클릭해 기록을 작성한다. 다이어리에서 같은 항목을 수정하고 날짜를 옮긴 후 양쪽에서 확인한다. 삭제도 양쪽에 반영되어야 한다.
5. 일정을 완료 처리한 후 `완료 N개`를 펼쳐 확인한다. 기본 일정 입력에서 제목 아래 내용·종일/시간·완료를 확인한다.
6. 긴 프로젝트 이름은 프로젝트 수정의 짧은 표시 이름, 긴 기록 제목은 기록 수정의 짧은 작업명을 설정한다. 원문 상세의 원래 제목은 유지되어야 한다.
7. 기존 설정 휠 스크롤, 위젯 이동·크기 변경, 글꼴/테마를 확인한다.

사용자 데이터와 실제 다중 모니터·배율 전환, 손으로 드래그할 때의 체감은 사용자 확인 대상이다. 자동 테스트와 합성 화면 검증이 PR 머지 승인을 대신하지 않는다.
