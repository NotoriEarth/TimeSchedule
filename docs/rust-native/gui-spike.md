# Rust GUI 시제품 — 2026-10-29

## 현재 결론

Iced 시제품 코드와 별도 실행 파일을 준비했다. **최종 GUI 채택 또는 전면 이식 승인 단계는 아니다.** 실제 Windows 한글 조합·배율별 화면·Explorer 바탕화면 동작 확인 후 판단한다. egui 비교는 Iced의 실제 실패가 확인되면 진행한다.

## 실행

```powershell
.\scripts\build-native-spike.ps1
& .\artifacts\TimeSchedule-rust-prototype.exe --probe=editor
& .\artifacts\TimeSchedule-rust-prototype.exe --probe=desktop
```

`editor`는 상세 다이어리 한 창, `desktop`은 상세창과 별도 위젯을 연다. 기본값은 editor이다. 모든 데이터는 합성 기록이며 **저장 버튼도 실행 중 메모리에만 저장**한다. 종료 후 기록은 사라진다. 사용자 DB, 설정 파일, Git 저장소, 서버에는 접근하지 않는다.

## 구현 범위

- 이미지의 배치에 맞춘 4열×2행: 첫 행 `개요, 월, 화, 수`, 둘째 행 `목, 금, 토, 일`.
- 날짜당 100개, 총 700개 합성 기록. 날짜별 스크롤 ID와 내부 스크롤 영역, 요약 펼치기, 메모리 검색.
- 여러 줄 편집기, 바깥 클릭 시 닫기, 수정 중이면 별도 중앙 미저장 확인. 계속 작성/Esc 복귀 및 앱 종료 의도 보존.
- Ctrl+Z, Ctrl+Y/Ctrl+Shift+Z: 최근 32개 편집의 텍스트·커서 스냅샷. 타이핑 묶음 최적화는 아직 없다. 본문 상한 UTF-8 300KB. 원문 스냅샷 이력은 최대 약 9.6MB에 부가 비용이 든다.
- IME 조합 감지 중에는 저장/이력 이동/닫기를 보류한다. 이는 상태 테스트를 통과한 방어 동작이며 실제 IME 호환성 통과를 의미하지 않는다.
- 위젯의 진단/바탕화면 연결/분리/40·82·100% 투명도/잠금·해제. 위젯 상단 날짜 영역이 이동 손잡이다. 바탕화면 연결은 자동 실행하지 않고 상세창 버튼으로 시험한다.

달력 날짜는 2026-10-26~11-01 고정이다. 월간 탐색, 링크 열기, 프로젝트 페이지, 실제 DB 저장/검색, 트레이, Git 수집, 동기화는 기존 앱에 남아 있으며 이번 시제품에는 이식하지 않았다. 노트 편집기를 포함한 UI 전체 기능의 동등성은 아직 충족하지 않는다.

## 고정 구성과 Windows 경계

- `iced = 0.14.0`, lockfile의 `iced_widget 0.14.2`, `winit 0.30.13`.
- 기본 feature를 끄고 `tiny-skia`, `thread-pool`, `advanced`만 사용. CPU 소프트웨어 렌더러 후보이며 GPU 렌더러와의 성능 비교는 하지 않았다.
- 한글 글꼴은 Windows 설치 글꼴 `Malgun Gothic`을 요청한다. 폰트 파일을 재배포하지 않는다.
- `build.rs`가 기존 `src-tauri/src/desktop.rs`로부터 OUT_DIR에 실험용 어댑터를 생성한다. Tauri 창 타입/serde 파생/opacity의 기대 클래스명만 정해진 문자열 개수 검사 후 치환한다. 기존 앱 소스는 수정하지 않는다. 향후 공통 코어/플랫폼 분리 전의 임시 연결이며 production 설계로 채택하지 않는다.
- Iced의 `window::run` 안에서 받은 HWND만 다룬다. 기존 소유 프로세스/스레드·DPI·부모 호스트·DC 스타일·롤백 검사를 보존한다. winit의 `Window Class`는 소스상 `CS_HREDRAW | CS_VREDRAW`로 등록되며 클래스 자체는 변경하지 않는다.
- Explorer 재시작, 외부 창 스타일 수정, 화면 배율 변경을 수행하지 않는다. DPI가 다르면 연결을 거부하고 이유를 표시한다. Iced의 실제 HWND 생성 DPI가 맞는지는 호스트에서 확인해야 한다.

## 검증 결과와 남은 확인

- release 자동 테스트: 10개 통과. 미저장 의도 보존, 빈 편집기 닫기, 한글 텍스트 undo/redo, 이력 상한, 조합 중 닫기 방어, 네이티브 실패 시 잠금 표시 유지, Windows layered-child fixture를 포함한다.
- 기존 Node 테스트 3개, `cargo fmt --check`, `git diff --check` 통과. Clippy는 현재 툴체인에 미설치여서 실행하지 못했다.
- 최종 release EXE: 3,316,736 bytes, SHA256 `F6880CCD1C335F269C601F079179981E51093AC747E72D80540D84D121863C20`. Cargo 의존성 트리에 `tauri`, `wry`, `webview2-com`이 없는 것을 확인했다. 파일 크기는 RAM 사용량이 아니다.
- 독립 코드 검토에서 발견한 기본 undo/redo 부재, Esc 포커스 복구, 잠금 표시 선반영 문제를 수정했다.
- 최초 release 실행 시 OS 창 목록에서 상세창/위젯 두 창을 확인했다. 프로세스 응답 상태는 True였다.
- 최종 수정 후 release도 실행하여 OS 창 목록의 시제품 창 2개를 재확인했다. 화면 내용·입력 동작의 확인을 뜻하지 않는다.
- 화면 조작 도구가 앱 접근 승인 시간 초과를 반환하여 스크린샷·실제 클릭·한글 조합 입력은 확인하지 못했다. 붙여넣기 또는 단위 테스트를 실제 IME 검증으로 대체하지 않았다.
- 800×620/기본 크기, 100%/200% 배율, 모달 배경 차단, 커서/선택 복원, 조합 중 Enter/Esc/마우스 닫기, 바탕화면 연결·투명도·Win+D·잠금·분리 후 재연결은 사용자 테스트 대상으로 남아 있다.

### 직접 확인 순서

1. editor 모드: 각 날짜를 따로 스크롤하고 기록을 펼친다. 다른 날짜가 함께 움직이지 않는지 확인한다.
2. 날짜의 `+ 추가`: “만년 다이어리 일정 기록”을 **한글 키보드로 조합 입력**한다. 중간 삽입/삭제, 한영 전환, 줄바꿈, 선택, Ctrl+Z/Y를 확인한다.
3. 편집기 바깥 클릭 → 미저장 팝업 → 계속 작성/Esc. 내용 유지와 바로 이어 쓰기를 확인한다. 앱 우측 X도 같은 보호를 확인한다.
4. 기록 저장은 시제품 메모리에 반영되는지 확인한다. 실제 일기나 보관할 내용은 입력하지 않는다.
5. desktop 모드: 위젯을 빈 바탕화면 영역에 둔 뒤 `바탕화면 연결`. 실패하면 표시된 오류를 기록한다. 성공하면 투명도, 날짜 손잡이 이동, 잠금, 위젯에서 상세창 열기, Win+D, 분리/재연결을 확인한다.
