# 전체 Rust 이식: 구현·검증 기록

기준 기능: PR #1의 PC 다이어리. Iced 0.14/tiny-skia와 공통 Rust SQLite/Git 코어로 실제 저장 가능한 별도 앱을 구현했다. 작업 승인·고정 소스·독립 검토는 `SOFTWARE_FACTORY.rust-native.md`에 기록한다. 외부 AI나 기기 간 동기화를 새로 구현한 것은 아니다.

## 기능 대조 기준

이 표의 구현은 코드·자동 테스트·독립 검토 기준이다. 실제 화면 배치·한글 IME·마우스 조작 전체를 통과했다는 뜻은 아니다. 독립 검토에서 발견한 오류를 수정하고 해당 수정 범위를 재검토했다.

## 경계

기존 앱과 사용자 DB는 기준판으로 보존한다. 새 앱은 별도 기본 폴더를 사용하며, 기존 DB 자동 복사/이전은 하지 않는다. 외부 AI·ChatGPT/Space·기기 간 동기화·모바일 앱·블록 편집기는 기존 버전에도 없는 후속 기능이므로 이번 이식 완료 항목에 포함하지 않는다.

## 실행과 소스 위치

```powershell
.\scripts\build-native.ps1
.\artifacts\TimeSchedule-native.exe
```

빌드된 실행 파일을 직접 열어도 된다. 기본 DB는 `%LOCALAPPDATA%\com.timeschedule.personal.native-experiment\schedule.db`이며, `TIMESCHEDULE_DATA_DIR`를 설정하면 해당 폴더를 사용한다. 새 앱 자체를 실행할 때 Python·Node.js·WebView가 필요하지 않다. 수동 Git 수집을 사용하려면 Git 실행 파일을 찾을 수 있어야 한다.

| 경로 | 책임 |
|---|---|
| `apps/timeschedule-native/src/app.rs` | 화면/창 수명, 비동기 응답, 저장·닫기·종료 상태 |
| `apps/timeschedule-native/src/views.rs` | 월간·주간·프로젝트·검색·편집기·위젯 |
| `apps/timeschedule-native/src/editor.rs`, `frozen.rs` | 편집 이력·조합 보호, 팝업 뒤 편집 위젯 상태 유지 |
| `apps/timeschedule-native/src/worker.rs` | SQLite/Git 작업과 데이터 전달 |
| `crates/timeschedule-core` | 저장·검색·Git·날짜·근거 초안 |
| `crates/timeschedule-desktop` | 소유 HWND 검증, Explorer 연결, 위치·투명도·트레이·설정·잠금 |
| `src-tauri/src/{storage,diary,desktop}.rs` | 기존 앱과 공통 코어 사이의 어댑터 |

관련 회귀 테스트는 해당 Rust 모듈의 `tests`와 `crates/timeschedule-desktop/tests/desktop_native.rs`에 있다. 원본 Svelte UI는 보존한다.

## 검증 결과

최종 실행 파일: `artifacts/TimeSchedule-native.exe`, **5,545,984 bytes (5.29MiB)**. SHA256: `30EE5BFB0BD7A9FFB4814DA18F31E4507FB74A46E7DDE2BE4339B303B17096BD`. `native-b2-release.log`의 release 빌드와 고정 소스 재검토를 완료했다. 사용자 확인 전 PR #2의 머지는 보류한다.

공통 코어 25개, 플랫폼 6개, Windows HWND 통합 fixture 1개가 통과했다. 별도로 ignored 처리된 자식 프로세스 fixture는 Git 제한 테스트가 직접 실행한다. 기존 Tauri 테스트 4개와 시제품 테스트 10개, 원본 프런트엔드 날짜·초안 테스트 3개도 통과했다. 공통 코어 수정 후 `scripts/build.ps1`의 Svelte 검사·Vite·Tauri release 빌드도 통과했다.

네이티브 앱 테스트는 21개가 통과했다. 다섯 종류의 작성·조회·수정·검색·삭제, 저장 실패 후 초안 보존, 오래된 응답 차단, 현재 범위가 준비되기 전 페이지 조회 차단, 다른 달에서도 오늘 일정 조회, 실제 Iced 위젯 트리의 입력 선택/포커스 유지와 팝업 배경 입력 차단을 포함한다. 첫 실행의 저장 좌표가 없는 경우는 테스트 소유의 숨긴 대형 HWND로 위치·크기 보정을 확인했으며, 실제 디스플레이 배율 변경 테스트는 아니다.

새 앱은 SQLite/Git/검색을 백그라운드에서 실행하고 화면 세대로 오래된 응답을 거른다. Git은 명령 실행에 공유 30초 예산과 stdout 8MiB/stderr 64KiB 제한을 적용한다. 종료 시 진행 중인 저장과 설정 쓰기를 기다린다. 상세창 닫기는 창을 숨겨 재사용하므로 닫을 때 메모리를 모두 반환한다고 주장하지 않는다.

최종 SHA256와 일치하는 실행 파일 복사본을 `.test-data/native-port-final-smoke`에서 실행하여 SQLite 초기화, 상세창·위젯 생성, Explorer 연결 `attached=true`, 표시 `visible=true`, 좌표 `(30,40)`, 설정 파일 생성과 프로세스 응답을 확인했다. 초기 제한된 실행 환경에서는 Explorer를 찾지 못했고 일반 Windows 세션에서는 연결됐다. 이 관측은 사용자 UI 수용 테스트를 대신하지 않는다. 실행 점검에 만든 프로세스만 종료했으며 사용자 앱은 유지했다.

최종 실행 후 빈 DB 1회 기록은 working set 28,549,120 bytes(27.23MiB), private commit 12,365,824 bytes(11.79MiB)였다. 이는 실제 여러 화면을 조작한 상태나 위젯만 남긴 상태의 측정이 아니며, private working set이나 기존 앱 대비 절감률도 아니다. 파일 크기와 RAM은 별개다.

화면 조작 도구는 창 목록과 제목은 읽었으나 캡처 시간 초과 후 최소화된 창 복구에 실패했다. 실제 한글 조합, 이미지와 화면 배치 일치, Win+D, 트레이 조작, Explorer 재시작, 다중 모니터와 200% 배율은 미검증이다. 현재 툴체인의 Clippy는 설치되어 있지 않아 실행하지 않았다. 후속 [20회 RAM/CPU 비교](benchmark.md)는 동일 합성 DB의 기본 월간 상세창+위젯 유휴 상태에서 완료했다. 위젯 크기는 서로 다르며, 검색·편집·위젯 단독·장시간 누수는 아직 측정하지 않았다.

## 사용자 확인 절차

아래는 새 네이티브 실행 파일의 수동 확인 절차이며 통과 결과가 아니다. 기본 폴더는 기존 앱과 분리되어 있으므로 처음 실행하면 비어 있을 수 있다. 실제 기록 이전은 별도 작업으로 진행한다.

1. 월간에서 날짜를 눌러 일정을 만들고, 해당 날짜의 제목·시간·색·완료·메모를 수정한다. 2026-10-25 일요일 앞 주간 버튼은 10-26~11-01을 열어야 한다. 월간 복귀는 원래 월이어야 한다.
2. 주간의 일곱 날짜와 개요가 한 화면에 보이는지 확인한다. 한 날짜의 기록을 많이 추가하거나 긴 본문을 펼쳐 그 칸만 스크롤되는지 확인한다. 날짜/추가 버튼과 다른 날짜의 위치는 유지되어야 한다.
3. 일정과 기록 편집기에 한글 키보드로 “만년 다이어리 일정 기록”을 조합 입력한다. 중간 삽입/삭제, 줄바꿈, 한영 전환, 선택·붙여넣기, 실행 취소/다시 실행, 조합 중 Enter/Esc를 확인한다. 붙여넣기만으로 IME 테스트를 완료하지 않는다.
4. 수정 없는 편집기는 바깥 클릭으로 닫힌다. 수정 후 바깥 클릭/창 X/완전 종료에는 확인이 있어야 한다. 계속 작성/Esc 후 내용·스크롤·편집 가능 상태를 확인한다. 명시적 버리기만 내용을 버려야 하며, 저장 오류가 나도 원문은 남아야 한다.
5. 프로젝트에 설명과 테스트용 로컬 Git 저장소 경로를 저장한다. 커밋 수집→기록 수정→재수집 시 중복과 수정 덮어쓰기가 없어야 한다. 출처 링크를 열고, 자유 노트/트러블슈팅/개발 기록을 각각 수정한다.
6. 주간/프로젝트 근거 요약과 포트폴리오 초안을 만들고 수정해 저장한다. 원문 기록을 덮어쓰지 않고 출처와 제한 안내가 있어야 한다. 생성 중 다른 화면으로 이동하거나 편집기를 열어도 뒤늦은 응답이 현재 편집을 덮어쓰면 안 된다.
7. 할 일의 날짜 있음/없음과 완료 전환, 메모의 제목/본문 수정을 확인한다. 한국어 제목·본문 검색에서 일정/기록/프로젝트/할 일/메모 각각을 열어 본다.
8. 앱을 완전 종료한 뒤 다시 열어 작성 데이터와 위젯 설정이 남는지 확인한다. 동일 데이터 폴더의 중복 실행은 기존 실행을 종료하거나 DB를 손상시키지 않고 안내해야 한다.
9. 위젯을 빈 바탕화면 영역에 놓고 불투명도·이동·잠금·위치 복구·숨김/표시를 확인한다. 위젯 날짜 클릭은 상세창의 해당 날짜로 이어져야 한다. Win+D와 일반 창 겹침에서도 동작을 확인한다.
10. 상세창 닫기/트레이 재열기 10회 후 날짜 선택과 저장이 계속 가능한지 확인한다. 위젯과 트레이는 상세창 닫기 뒤에도 남고, 완전 종료 후에는 모두 사라져야 한다.
