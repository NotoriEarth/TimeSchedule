# 작업 종료 기록과 연결 복구 전달

사용자 보정: 별도 오전 9시 포트폴리오 작성을 중지한다. 작업 종료마다 기록하고, Space 장애 중에도 다이어리에 상세 원문을 남긴다. 앱 실행 중에는 대기 기록만 자동 재시도하며 복구되면 누적 내용을 모두 전달한다. Space→PR 선택적 재사용과 사용자 확인 후 머지 원칙은 유지한다. 기존 설계의 Space 성공 선행 조건·오전 9시 보충 부분은 이 보정으로 대체한다.

같은 미병합 PR #8의 `codex/automatic-project-records` 브랜치에서 이어 구현한다. 0.8.0의 미출시 후속 보정으로 버전은 유지한다. 구현은 현재 세션에서 진행하고 마지막에 독립 리뷰를 한 번 수행한다.

1. 공통 기록 v2: 링크 없는 pending 상태에 전체 상세 원문을 저장하고, 별도 증가 revision의 synced 상태로 같은 항목에 검증된 링크를 연결한다. v1 입력·기존 receipt payload를 호환한다. 사용자가 수정·삭제한 항목은 덮어쓰지 않는다. 전체 원문은 링크 연결 후에도 보존한다.
2. Node 전달: 로컬 수신 완료를 먼저 확인한 뒤 게시한다. known-no-write 연결 실패는 재시도 가능하게, 불확실한 생성은 기존 페이지 확인만 허용한다. 여러 작업과 같은 작업의 누적 revision을 잃지 않고 처리한다. 실패 간격은 점진적으로 늘리며 완료·충돌 작업에는 모델 호출을 하지 않는다. 새 입력은 준비만으로 끝내지 않고 항상 sync를 실행한다.
3. 네이티브 앱: 명시적으로 등록한 이 저장소의 스크립트·Node·상태 폴더만 실행한다. 앱 실행 중 주기적으로 대기 파일만 확인해 hidden retry 프로세스를 하나 실행한다. DB inbox 처리는 계속 독립적으로 진행한다. 등록 정보는 재시작 후 유지한다. child lifetime은 제한하고 앱을 막지 않는다. 기존 오전 9시 자동화는 PAUSED로 전환한다.
4. 검증/릴리스: offline→다이어리 원문→여러 대기 항목→복구→같은 항목의 링크 연결, 중간 실패·동시 실행·사용자 편집 보존·v1 호환을 테스트한다. 최종 단일 EXE와 실제 Space/격리 DB 및 실행 중 앱 재시도를 확인한다. 필요한 테스트·커밋·푸시·PR 갱신 후 사용자 테스트 전 머지하지 않는다.

검토 집중: synced가 같은 revision의 pending receipt와 충돌하지 않는가; 새 작업이 이전 미전송 원문을 잃지 않는가; 전송 프로세스 실행 중에도 GUI 수신 처리가 진행되는가; 앱 재시작·CLI 접속 실패 후 중복 페이지 없이 복구되는가; 실패한 선두 작업이 뒤의 정상 대기 작업을 막지 않는가.
