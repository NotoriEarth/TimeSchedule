# 카테고리와 다이어리·위젯 공통 날짜 항목 구현

> 사용자는 2026-11-03 상단 카테고리 버튼 1안을 선택하고 실제 구현 및 양방향 작성/수정 연동을 요청했다. `superpowers:executing-plans`로 현재 작업 브랜치에서 구현한다. 이 문서는 앞선 재작성 대기 실행 초안을 대체한다.

**Goal:** 다이어리와 위젯이 같은 일정·기록·카테고리를 읽고 수정하며, 저장 직후 두 화면이 함께 갱신된다.

**Architecture:** 기존 SQLite 원본과 ID, 일정 MCP를 보존한다. 공통 날짜 조회와 부가 메타데이터를 코어에 추가한다. UI는 같은 날짜 항목·상세·Form을 재사용하며 저장/삭제/범위 변경에만 조회한다.

**Tech Stack:** Rust/Iced 0.14, SQLite/rusqlite, 기존 네이티브 창. 서버·웹뷰·추가 상주 프로세스 없음.

**Spec:** `docs/superpowers/specs/2026-11-03-calendar-categories-discussion.md` 및 이 문서의 구현 결정. 기본 두 줄 시안만 구현한다.

## 확정 구현 결정

- 카테고리 버튼은 다이어리 월간/주간 상단의 추가 버튼 왼쪽이다. 작은 공통 관리창에서 추가·이름·색·드래그 순서 및 키보드 위/아래 이동을 제공한다.
- 기본 카테고리는 일정/기록이고 기본 순서는 1/2다. 새 카테고리는 기록형 공통 입력(제목·내용·날짜·선택 프로젝트)을 사용한다. 모든 카테고리의 순서·색은 양쪽 화면에서 공유한다.
- 일정/할 일은 화면과 입력을 통합한다. 기존 ID·MCP 호환을 위해 원본 테이블은 보존하고, 기존 할 일에 본문·종일/시간 부가 정보를 더한다. 날짜 없는 일정은 별도 미배정 목록에 유지한다. 여러 날짜에 걸친 일정·반복·알림은 이번 범위가 아니다.
- 날짜 항목은 현재 화면의 날짜 범위로 독립 조회한다. 앱에서 프로젝트 화면을 선택해도 위젯의 범위를 바꾸지 않는다. 표시 날짜가 다르면 다른 날짜 항목을 억지로 복제하지 않는다.
- 카테고리 순서대로 미완료 일정과 두 줄 기록을 채우고 완료 일정은 `완료 N개`로 접는다. 기록은 프로젝트명(없으면 카테고리명) / 짧은 제목이다. 숨긴 전체 개수는 본문 없는 집계로 정확하게 유지한다.
- 달력 조회는 날짜당 최대 16개 미완료 머리말, 날짜 상세는 50개 페이지다. 기록 원문/일정 설명은 상세 선택 때만 읽는다. 사용 가능 공간만큼 온전한 줄을 표시하며 프로젝트명 토글은 구현하지 않는다.
- 원래 기록 제목/본문/수신 영수증을 보존한다. 선택적 짧은 작업명과 프로젝트 표시 이름은 별도 메타데이터다. 사용자 편집 충돌과 오래된 비동기 응답은 덮어쓰지 않는다.
- 기존 종류 6종은 기록 원본/세부 종류로 보존하고 기본 기록 카테고리에 연결한다. 새 분류 생성은 AI 호출이나 자동 Git 수집을 시작하지 않는다.
- 스키마 3→4는 기존 행을 복사/삭제하지 않고 테이블과 인덱스를 추가한다. 파일 DB는 최초 이전 전 일관된 백업을 만든다. 실행 중인 사용자 앱의 데이터/EXE는 강제 변경하지 않는다.

## Review Focus

1. 월/프로젝트 목록의 200개 제한과 독립 위젯 날짜 범위로 인한 누락·잘못된 개수.
2. 본문/카테고리/짧은 이름 저장의 원자성, 수신 중 사용자 편집 보존, 기존 일정 MCP CAS 호환.
3. 위젯에서 만든 항목의 앱 표시 및 반대 방향, 날짜 이동·삭제·완료·새 카테고리 이후 열린 상세 갱신.
4. 카테고리 드래그가 놓을 때만 저장되는지, 행/날짜 더블클릭 이벤트 전파, 작은 창과 배율에서 겹침.
5. 모든 날짜 본문 조회/일별 쿼리 반복/새 폴링 없이 조회가 제한되고 미저장 초안·늦은 응답을 보존하는지.
