# Git 기록을 재사용하는 Space와 다이어리 자동 기록

상태: 사용자 검토용 설계. 아직 기능 구현이나 자동화 설정 변경을 하지 않았다.

## 사용자가 정한 목적

- 여기서 프로젝트를 진행하며 남기는 개발 설명을 포트폴리오로 축적한다. 특히 작업 배경, 문제, 시도, 확인한 원인, 해결 과정, 검증 결과, 배운 점과 PR·커밋 근거가 중요하다.
- Git에 기록할 때 작성한 내용을 최대한 재사용한다. 세 저장 위치의 문장이 완전히 같을 필요는 없다.
- Space에는 상세 기록, TimeSchedule 다이어리에는 날짜·프로젝트·짧은 요약·Space 링크를 자동으로 남긴다. 다이어리에서 링크를 열어 상세 기록으로 이동한다.
- 불필요한 모델 호출을 줄이고, 요약이 필요하면 내용을 왜곡하지 않을 수준의 저비용 모델을 쓴다.
- 기존 사용자 테스트 후 PR 병합 절차, 단일 대표 EXE, 기존 데이터와 사용자 편집을 보존한다.

## 확인한 현재 상태

- 네이티브 0.7.0은 Rust/Iced 앱이다. `timeschedule-core`에 프로젝트·다이어리 저장과 검색, 원문·출처 식별자 저장이 있다. GUI에는 `출처 링크 열기`가 있다. 외부 기록을 받는 CLI는 없다.
- 기본 네이티브 DB는 `%LOCALAPPDATA%/com.timeschedule.personal.native-experiment/schedule.db`이다. `TIMESCHEDULE_DATA_DIR` 재정의와 데이터 폴더별 GUI 인스턴스 잠금이 있다.
- GitHub `NotoriEarth/TimeSchedule` PR #7에는 이미 변경 이유, 해결 방식, 검증 결과와 검증 범위가 기록되어 있다.
- 기존 Space 목적지는 `https://chatgpt.com/space/page_6ae1b18a44f08191ad2a86276972476c`이다. 제목은 `TimeSchedule 개발 포트폴리오`, 상위는 `개발 공부`이며 현재 계정에 읽기·쓰기 권한이 있다.
- 기존 Codex heartbeat `timeschedule`은 매일 오전 9시 실행으로 활성화되어 있다. 대상 채팅은 `01a18198-e66f-7b22-a330-43c610a9f7cc`이다. 별도의 Page controller나 연결된 Page automation은 없다. 기존 작업을 재사용하고 중복 생성하지 않는다.
- 2026-10-31 일반 Windows 계정에서 Codex CLI 0.163.0의 `model/list`로 `gpt-6-luna`와 medium reasoning 지원을 확인했다. `app/installed`에서 `connector_openai_pages`는 enabled=true, callable=true였다. 실제 Luna 요약·CLI Page 쓰기는 아직 시험하지 않았다.

## 접근 방식과 제안

1. **공유 기록 재사용 + 작업 종료 시 전달 + 기존 자동화로 누락 보충**을 제안한다. 개발 작업에서 작성한 근거와 설명을 PR, Space, 다이어리에 함께 쓴다. 이 채팅에서 PR 준비·병합을 마칠 때 전달하고, 기존 오전 9시 작업은 누락·변경·실패를 보충한다. 새 상주 AI 프로세스가 필요 없다.
2. 매번 전체 채팅과 저장소를 새로 요약하는 방식은 호출 비용과 사실 변형 가능성이 커서 요구와 맞지 않는다.
3. Git의 모든 commit hook에서 즉시 게시하는 방식은 중간 커밋·검증 대기 기록이 과도하게 쌓이고 원격 병합을 놓칠 수 있어 첫 범위로 선택하지 않는다.

첫 구현 범위는 이 저장소와 위 Space 목적지이다. 다른 프로젝트는 명시적인 저장소·다이어리 프로젝트·Space 목적지 매핑을 추가할 수 있게 하되, 사용자의 다른 프로젝트와 채팅을 자동 탐색하지 않는다. 아래 세부 방식은 구현 제안이며 아직 사용자의 설계 승인을 받지 않았다.

## 하나의 작업 기록을 재사용한다

- 작업마다 `docs/development-records/<stable-work-id>.md`에 재사용할 기록을 작성한다. Git에 넣을 수 있는 프로젝트 설명과 근거만 포함한다. 작업 중 확인한 실패·원인·검증 한계를 이 단계에서 남겨 나중에 커밋으로 추측하지 않는다.
- 기록은 제목, 작업 ID, 프로젝트, KST 날짜, 배경, 문제·시도·확인한 원인·해결, 검증 결과와 한계, 배운 점, 짧은 다이어리 요약, 근거 링크를 포함한다. 해당 없는 항목을 억지로 채우지 않는다.
- PR 설명은 이 기록을 활용하고, Space 본문과 다이어리 요약도 같은 원문을 재사용한다. PR 생성 전에는 작업 ID를 사용하며 PR 생성 후 번호·URL·head SHA를 연결한다. PR URL을 넣으려고 기록용 커밋을 반복 생성하지 않도록 원격 메타데이터는 전달 시 결합한다.
- 기존 PR의 과거 기록을 가져올 때는 PR 본문·검증 문서·명시된 사용자 확인만 사용한다. 실패 시도나 개인 기여가 근거에 없으면 생성하지 않는다.
- PR 준비, 사용자 확인, 병합 상태는 별도로 보관한다. GitHub 병합 상태를 사용자 인수 테스트 증거로 해석하지 않는다. 사용자가 여기서 확인한 내용은 범위와 함께 기록한다.
- PR을 준비할 때는 `검증 대기`, 사용자 확인 후에는 해당 확인 결과, 병합 후에는 병합 SHA와 완료 상태를 동일 작업에 반영한다. 일상 대화·조사만 진행된 턴은 자동 게시 대상이 아니다.

## 전달 경로와 중복 방지

1. 작업 종료 절차에서 재사용 가능한 원문과 원격 PR 메타데이터를 결합해 불변 전달 파일을 만든다. AGENTS.md에 이 절차를 포함해 매번 사용자에게 기록 여부를 다시 묻지 않는다.
2. 기록용 Codex CLI 실행은 Pages 도구로 해당 작업의 Space 페이지를 생성하거나 갱신하고, 읽기 결과로 본문과 URL을 확인한다. 결과는 기계 판독 가능한 형식으로 받는다. 실패를 성공으로 추측하지 않는다.
3. 다이어리 입력 명령은 검증된 Space URL, 프로젝트, 날짜, 원문 식별자, 요약을 받는다. 같은 `TimeSchedule.exe`의 비 GUI 모드로 제공해 사용자 실행 파일을 늘리지 않는다.
4. 전달 상태는 로컬에 `prepared → space_saved → diary_queued → complete`로 보관한다. 재시도는 확인된 단계 다음부터 수행한다. 같은 작업 ID·내용 해시·PR 상태이면 모델 호출과 외부 쓰기를 생략한다.
5. Space 쓰기 성공 직후 연결이 끊겼다면 기존 매핑 또는 대상 부모 내 작업 식별자·정확한 PR URL을 조회해 결과를 확인한다. 결과가 모호하면 중복 페이지를 만들지 않고 보류한다.
6. 초기 활성화 시 해당 저장소의 현재 HEAD와 PR 상태를 체크포인트로 저장하고, 활성화 이후 준비·변경·병합된 작업을 보충한다. 활성화 전에 완료된 과거 PR을 일괄 게시하지 않는다. 이는 앞으로의 자동 기록이라는 요청에 따른 구현 제안이며, 과거 전체 보충은 별도 요청 범위다. 이 기능을 구현하는 작업 자체는 완료 절차에서 명시적으로 첫 기록에 포함한다. 원격 PR 조회는 해당 저장소와 체크포인트에 한정하되 해당 범위의 페이지는 끝까지 확인한다.

Space는 기존 포트폴리오 페이지 아래에 작업별 상세 페이지를 두고, 상위 페이지에는 짧은 요약과 링크를 연결하는 방식을 제안한다. 기존 포트폴리오의 사례·측정·개발 이력을 통째로 교체하지 않는다. 이미 같은 작업의 기록이 있으면 연결·보완하며 새 기록을 중복 생성하지 않는다. 기존 자동화도 같은 매핑과 전달 상태를 사용하도록 조정한다.

## 앱 실행 중에도 안전하게 다이어리에 반영한다

- 외부 기록 명령은 우선 앱 데이터 폴더의 전용 inbox에 검증한 JSON을 원자적으로 저장한다. 입력 크기, 필수 필드, 날짜, URL, 프로젝트 매핑을 검사한다. 파일 이름은 검증한 작업 키의 해시로 결정한다.
- GUI가 실행 중이면 GUI의 저장 작업자가 inbox를 처리한다. CLI가 GUI 잠금을 무시하고 DB를 수정하거나 앱을 종료하지 않는다. GUI가 꺼져 있고 CLI가 동일 인스턴스 잠금을 획득하면 공통 저장 모듈로 반영하고 종료할 수 있다.
- GUI는 시작 시와 최대 60초 간격으로 작은 inbox만 확인한다. 네트워크·모델 호출이나 Git 전체 탐색을 GUI 타이머에 넣지 않는다. 작업자는 기존 저장 방식으로 반영하고, 미저장 편집을 보존하며 목록 갱신을 통지한다.
- DB에는 작업 식별자를 기준으로 생성·갱신하고 마지막 자동 생성 본문과 사용자 편집 여부를 비교한다. 사람이 바꾼 제목·본문·날짜·프로젝트·출처 링크는 자동으로 덮어쓰지 않는다. 충돌 결과를 보관하고 필요한 경우만 알린다.
- CLI 응답은 `queued`와 `saved`를 구분한다. 큐 저장만으로 다이어리 저장 완료라고 보고하지 않는다. 앱이 다음에 열릴 때 남은 큐를 처리한다.
- 기본 경로와 `TIMESCHEDULE_DATA_DIR` 처리는 기존 앱과 일치시킨다. Tauri DB로 자동 이전하거나 다른 사용자 DB를 선택하지 않는다. 첫 설치에서 매핑이 없으면 저장소 절대 경로에 해당하는 프로젝트를 한 번 생성·연결한다. 같은 경로가 여러 프로젝트에 있으면 임의 선택하지 않는다.

## 모델과 사실 보존

- 이미 충분한 원문·짧은 요약이 있으면 별도의 요약 생성 호출을 하지 않는다. 다만 Pages를 실행하는 Codex 도구 호출 자체에는 모델 처리가 필요할 수 있다.
- 기록 전용 실행의 첫 후보는 `gpt-6-luna`, reasoning `medium`이다. 기존 ChatGPT 로그인으로 실행하고 API 키를 새로 요구하지 않는다. 개발 본작업의 모델 설정은 변경하지 않는다.
- 모델 선택은 비용을 근거로 한 후보 결정이다. 무왜곡을 보장한다고 설명하지 않는다. 활성화 전에 실제 프로젝트 사례로 모델이 근거·부정 표현·검증 한계를 보존하는지 확인한다.
- 요약 입력은 해당 작업 원문·필요한 검증 근거로 제한한다. 전체 저장소·전체 채팅을 반복 전송하지 않는다. 공식 CLI의 구조화 출력으로 요약 항목과 근거 문단 ID를 받는다.
- 기본 방식은 근거 문단을 선택해 발췌하고 원문 표현을 유지한다. 결과와 그 한계가 함께 있는 문단을 분리하지 않는다. PR 번호·SHA·날짜·수치·URL은 입력에서 직접 복사한다.
- 구조 오류, 없는 근거 ID, 수치 불일치, 근거 부족이면 원문 기반 기록으로 돌아간다. 고비용 모델로 몰래 전환하거나 성공 사례처럼 내용을 채우지 않는다. 의미가 불확실한 기록은 원문 링크와 함께 보류한다.
- 단가표를 CLI 구독 사용료로 환산하지 않는다. 모델 호출 횟수와 전달 결과를 남겨 불필요한 반복을 확인한다. 변경 없는 실행은 모델 요약과 Page 수정을 생략한다.

## 기존 자동화와 실행 조건

- 기존 `timeschedule` heartbeat의 시간·대상 채팅은 유지하고, 프롬프트를 공통 원문·전달 상태 재사용 중심으로 수정한다. 변경 없음은 조용히 종료하고 의미 있는 완료·실패·필요한 사용자 조치만 알린다.
- heartbeat는 기존 채팅 실행 모델을 상속할 수 있다. 이를 저비용 모델로 바꿨다고 주장하지 않는다. 필요한 기록 처리는 명시적으로 지정한 Luna CLI 실행으로 수행하고 새 cron 작업을 우회 생성하지 않는다.
- 작업 종료 시 전달은 이 저장소의 Codex 작업 절차가 담당한다. 매 턴의 완료 여부를 자연어로 추측하는 hook을 설치하지 않는다. 이 경로를 거치지 않은 원격 변경은 기존 오전 9시 자동화가 보충한다.
- PC·Codex 실행 환경·로그인·네트워크가 없으면 즉시 외부 반영할 수 없다. 상태를 보존하고 다음 작업 종료 또는 자동화 실행에서 재시도한다. 기록 실패가 개발 작업이나 PR 병합 자체를 취소하지 않는다.
- 일반 CLI의 Pages 사용 가능 상태는 확인했지만 실제 생성·재조회는 구현 검증에서 수행한다. 권한·로그인이 차단되면 로컬 기록을 보관하고 정확한 실패 사유를 알린다.

## 완료 판정과 전달

1. 재사용 가능한 기존 기록은 별도의 요약 호출 없이 Space·다이어리에 전달된다. 같은 작업을 재실행해도 중복되지 않는다.
2. 준비·사용자 확인·병합 상태 변경이 같은 기록에 반영되고, 부정 결과와 미검증 항목이 완료로 바뀌지 않는다.
3. GUI 실행·종료, 큐 재시작, DB 잠금, Space 성공 후 다이어리 실패, 연결 단절 후 재시도, 사용자 편집 충돌을 검증한다.
4. 기존 v2 DB의 데이터 보존과 새 DB 생성, 프로젝트 매핑, 한국어 요약·URL, 검색·날짜별 표시와 링크 열기를 확인한다.
5. 모델 검증 자료에는 RAM 감소와 CPU 증가가 함께 있는 사례, 일부 테스트 미실행, 확정되지 않은 원인, 재현·수정·재검증의 순서가 포함된다. 원문에 없는 사실을 생성하거나 한계를 지우면 해당 요약을 채택하지 않는다.
6. 격리된 로컬 DB로 자동 검증 후 실제 테스트용 Space 기록과 다이어리 왕복을 확인한다. 실제 사용자 데이터에 반영한 범위와 아직 미확인인 범위를 구분한다.
7. 기능 구현 시 0.8.0으로 올리고 CHANGELOG·README·잠금 파일을 맞춘다. 대표 `artifacts/TimeSchedule.exe`를 빌드하되 실행 중이면 강제로 교체하지 않는다. 검증·커밋·푸시·PR을 준비하고 사용자 테스트 승인까지 병합을 보류한다.
