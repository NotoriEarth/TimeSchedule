# PC 만년 다이어리

사용자는 2026-10-29 개발 시작을 명시적으로 요청했다. 추가 승인 대기 없이 이 대화의 요구를 구현한다. 현재 작업 브랜치: codex/perpetual-diary. main에서 수정하지 않는다.

## 요구
- 상세 창이 메인 만년 다이어리다. 종이 다이어리 느낌의 차분한 한국어 월간/주간 화면. 기존 반투명 Windows 바탕화면 위젯과 트레이 동작 보존.
- 상세 창 월간 화면의 일요일 앞 주간 선택 영역: 해당 일요일 다음 월요일~다음 일요일 강조, 클릭하면 같은 창에서 주간으로 전환. 월간으로 돌아가면 이전 월 유지. 월경계/연경계 처리.
- 날짜 클릭으로 선택 날짜 일정 추가. 주간은 고정 칸 수 없이 항목을 추가하고 한 줄 요약을 펼쳐 상세/출처 링크 확인.
- 프로젝트 생성 및 수정, 프로젝트별 자유 노트/트러블슈팅, 날짜별 개발 기록을 공유. 제목/본문/프로젝트 설명은 계속 수정 가능.
- 로컬 Git 저장소에서 커밋을 수집하고 출처/커밋 ID로 중복 방지. 트러블슈팅은 직접 작성 가능. 근거에 기반한 프로젝트/주간 요약 및 포트폴리오 초안을 수정하고 저장 가능. 사용자 필기를 자동 덮어쓰지 않음. 외부 AI 및 ChatGPT/Space 연결은 계정/정책이 미정이므로 실제 연결 완료로 표시하지 않음.
- 검색: 한국어 제목/본문, 일정/노트/프로젝트/개발 기록을 찾고 해당 위치 열기. 입력 지연 적용, 결과 수 제한, 최신 요청 결과만 반영. 위젯은 전체 노트 본문을 읽지 않음.
- 모든 편집은 로컬 영속 저장. 기존 v1 DB 데이터 보존. 잘못된 입력/실패한 수정은 기존 데이터 보존.
- 모바일/다른 기기/동기화 서버/E2EE/CRDT/네이티브 Rust 화면 이식은 후속 작업이다. 현재 Rust+Tauri+Svelte+SQLite 유지, 새 상주 Python 서비스 없음.

## 결정
현재 스택 유지가 기능 완성 및 편집기 확장에 가장 적합하다. 전체 Rust 화면 재작성과 Python+Rust 혼합을 비교했으나 현재 Python 제품 코드는 없고 과거 측정은 WebView 비중이 높았다. 안정화 이후 별도 브랜치에서 렌더러 변경을 비교한다.

## 검증 및 전달
일정 주간 범위, DB migration/reopen, 수정/삭제, 한국어 검색, Git 재수집 중복, 원문 보존 테스트. npm check/build 및 Rust 테스트/포맷, Windows 릴리스 실행 파일 준비. 실제 UI 확인 범위와 미확인 동작 명시. 커밋/푸시/PR/채팅 연결 후 사용자 테스트 전 머지하지 않는다.
