# 위젯 날짜 칸 가독성 설계

상태: 2026-11-16 사용자가 세 방안 중 **A안 — 칸 안 구조 고치기**를 선택했다. 이 문서의 승인 후 구현한다. 아직 소스는 바꾸지 않았다.

## 목적

바탕화면 위젯의 월 표시에서 날짜 칸의 일정·기록 글씨가 한눈에 읽혀야 한다. `+N개 더`는 무엇이 숨었는지 알려 주지 않아 쓸모가 없다는 것이 사용자의 판단이다.

- 목표: 같은 칸에 더 큰 글씨로 더 많은 항목을 보여 준다. 숨은 항목도 숫자가 아니라 제목으로 보여 준다.
- 하지 않는 것: 주 높이 자동 배분(B안), 옆 일정 목록(C안), 마우스 올림 펼침, 글씨 그림자, 새 설정 항목.
- 피할 것: 새 라이브러리·상주 작업·주기 타이머, CI 시간이 늘어나는 검사.

## 지금 구조와 원인

`calendar_ui::day_items`가 위젯 칸(`desktop_widget.rs`)과 다이어리 월 칸(`shell.rs`)을 함께 그린다. 줄 하나는 `item_view`이며 날짜 창·다이어리 옆 목록도 같은 `item_view`를 쓴다.

사용자 저장 설정(위젯 963×646, 일정 글자 11, 날짜 글자 15, 셀 안쪽 6, 줄 간격 3, 월 표시)으로 계산하면 다음과 같다.

| 항목 | 지금 |
|---|---|
| 일정 한 줄 높이 | 11×1.3 + 6 + 3 = 23.3px (글씨는 14px) |
| 기록 한 줄 높이 | 프로젝트명·작업명 두 줄이라 39.6px |
| 제목에 쓰는 너비 | 칸 122px 중 색 막대·체크박스·여백 34px를 뺀 88px |
| 날짜 숫자 줄 | 20.5 + 4 = 24.5px |
| 5주 달의 칸 | 일정 2개 또는 기록 1개, 나머지는 `+N개 더` |
| 6주 달의 칸 | 기록이 여럿이면 하나도 못 들어가고 `+N개 더`만 남음 |

## 검토한 방식

| 방식 | 차이 | 선택 |
|---|---|---|
| A. 칸 안 줄 구조를 고친다 | 화면 구조·설정 항목은 그대로. 변경 범위가 가장 작다 | 사용자 선택 |
| B. A + 일정 많은 주를 높게 | 넘치는 날이 더 줄지만 배치 계산이 늘어난다 | 미선택. A 사용 후 판단 |
| C. A + 옆에 오늘·다가오는 일정 목록 | 가장 확실히 읽히지만 칸이 좁아진다 | 미선택 |

## 설계

### 칸 전용 줄 (위젯 칸과 다이어리 월 칸)

`day_items`가 칸 전용 줄을 직접 그린다. 날짜 창과 다이어리 옆 목록의 `item_view`는 바꾸지 않는다.

- **줄 높이**: 글자 크기 × 1.3 + 줄 간격 설정. 버튼 여백과 체크박스 높이를 없앤다.
- **줄 구성**: 카테고리 색 막대 3px, 간격 4px, 글씨. 줄 배경에 카테고리 색을 옅게 깐다.
- **일정**: `HH:MM`은 옅은 보통 굵기, 제목은 굵게. 종일 일정은 제목만.
- **기록**: 한 줄. 프로젝트 짧은 이름(없으면 프로젝트 제목)을 카테고리 색 머리말로 붙이고 작업명을 굵게 쓴다. 프로젝트가 없으면 작업명만 쓴다. 머리말은 줄 너비의 40%까지만 쓴다.
- **체크박스**: 칸에서는 뺀다. 완료 처리는 날짜 더블클릭으로 여는 날짜 창과 다이어리 옆 목록에서 한다.
- **줄 클릭**: 지금처럼 그 항목의 상세를 연다.
- **남는 줄이 있을 때**: 모든 항목이 들어가고도 줄이 남으면, 제목이 잘린 항목부터 위에서 차례로 두 번째 줄을 준다(항목당 최대 2줄, 둘째 줄 끝은 말줄임).

### 넘칠 때의 마지막 줄

`+N개 더` 대신 숨은 항목의 제목을 이어 쓴다.

- 형식: `장보기 · CI 속도 정리`. 다 못 쓰면 `장보기 +2`.
- 완료 항목이 있으면 뒤에 `완료 2`를 붙인다.
- 제목이 하나도 못 들어갈 만큼 좁으면 `+N`만 쓴다.
- 옅은 보통 굵기로 칸 맨 아래에 두고, 누르면 지금처럼 날짜 창을 연다.
- 날짜 조회는 이미 날짜당 16개까지 읽으므로 새 조회는 없다.

### 위젯 틀

- 날짜 숫자와 항목 사이 간격 4 → 2px.
- **아래쪽 바를 없앤다.** `위치 잠금/잠금 해제`는 위쪽 버튼 줄(오늘·다이어리·설정 옆)로 옮긴다. 배경 투명도 슬라이더는 다이어리 설정에 이미 있으므로 위젯에서는 뺀다. 안내 문구는 없앤다.

### 기본값

| 설정 | 지금 | 새 기본값 |
|---|---|---|
| 일정 글자 | 11 | 13 |
| 날짜 글자 | 15 | 13 |
| 셀 안쪽 | 6 | 4 |
| 일정 줄 간격 | 3 | 1 |

- 이미 저장된 값은 건드리지 않는다. 사용자는 **설정 → 글꼴·간격·색상 초기화**를 한 번 눌러 새 기본값을 받는다(내 판단: 저장된 값이 예전 기본값과 같은지로 자동 변경하면 사용자가 일부러 고른 값과 구분할 수 없다).
- 밀도 프리셋 `기본`은 새 기본값과 맞추고, `촘촘`·`넉넉`은 같은 비율로 조정한다.
- 다이어리 월 칸의 고정 글자 크기는 11 → 12로 올린다.
- 설정 화면의 `+N개 더` 안내 문구를 새 동작에 맞게 고친다.

### 기대 결과 (계산값, 5주 달·위젯 963×646)

| | 지금 | 저장된 설정 그대로 | 새 기본값 |
|---|---|---|---|
| 줄 높이 | 23.3 / 39.6px | 17.3px | 17.9px |
| 칸에 들어가는 줄 | 일정 2 또는 기록 1 | 4줄 (11px) | 4줄 (13px) |
| 제목 너비 | 88px | 115px | 119px |

줄 수는 아래쪽 바 제거로 주마다 생기는 약 9px를 포함한 값이다. 6주 달은 한 줄 적다. 칸 높이는 코드의 치수로 추정한 것이므로 실제 값은 구현 후 렌더링 테스트와 미리보기 이미지로 확인한다.

## 검증

- 기존 넘침 테스트 4개를 새 동작에 맞게 고친다(먼저 실패를 확인한다).
- 추가: 주어진 높이에 들어가는 줄 수, 마지막 줄에 숨은 제목이 들어가는지, 어떤 글씨도 칸 밖으로 나가지 않는지(글자 9·13·24), 기록이 한 줄인지, 남는 줄에서 두 줄 제목이 되는지.
- 수동 미리보기 테스트로 위젯·다이어리 이미지를 두 테마에서 만들어 직접 본다.
- 바탕화면 그림 위 체감, 실제 마우스 조작은 사용자 확인 대상이다.
