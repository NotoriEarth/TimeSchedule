# 한 프로젝트의 하루 기록을 달력에서 한 줄로 묶기

상태: 구현됨(0.18.0). 사용자 화면 확인 전.

## 의도

같은 날 같은 프로젝트에서 한 작업이 여러 기록으로 남으면 달력 칸이 그 프로젝트의 줄로 가득 찬다. 사용자는 프로젝트당 한 줄만 보고, 열었을 때 세부 기록을 카드로 하나씩 보기를 원했다. 위젯과 다이어리 달력 모두에 적용한다.

- 목표: 하루에 프로젝트당 한 줄. 누르면 카드 목록. 카드에서 각 기록을 읽고 수정.
- 하지 않는 것: 저장된 기록을 합치기, 기록 화면(목록)의 묶기, 프로젝트 없는 기록 묶기.
- 실패로 보는 것: 자동 개발 기록의 갱신·충돌 보호가 깨지는 것, 묶인 기록을 개별로 열 수 없게 되는 것.

## 검토한 방법

1. **조회에서 묶기(선택).** 달력 조회가 날짜·프로젝트마다 가장 최근에 바뀐 기록 하나와 개수를 돌려준다. 저장 구조와 자동 기록 경로는 그대로다.
2. 저장에서 합치기. 한 프로젝트·하루의 기록을 한 항목으로 저장하고 세부를 하위 항목으로 둔다. 스키마 변경과 이전이 필요하고, 작업 ID마다 한 항목을 갱신하는 자동 기록의 멱등·충돌 보호를 다시 만들어야 한다.
3. 화면에서만 묶기. 이미 읽은 항목을 UI가 묶는다. 날짜당 16개만 읽으므로 개수와 `전체 N개`가 틀린다.

## 결정

- 묶는 기준은 날짜 + 프로젝트. 줄의 제목·카테고리 색은 가장 최근에 바뀐 기록의 것. 뒤에 `+N`.
- `전체 N개`와 숨은 항목 수는 줄 기준.
- 카드: 제목, 기록 종류, 본문 앞 4줄 또는 220자, `전체 보기`/`접기`, `출처 열기`, `수정`. 최근 50개.
- 카드에서 연 편집 화면이 닫히면 카드로 돌아온다. 화면을 새로 읽을 때마다 카드도 다시 읽는다.
- 그날 창과 다이어리 옆 목록의 기록도 날짜 칸과 같은 한 줄로 맞춘다.
- 사용자 추가 요청: 편집 화면의 `삭제`를 `수정`·`저장하기`와 다른 자리(입력란 끝)로 옮긴다.
- 스크롤바는 내용 옆에 자리를 따로 둔다(간격 6).

## 남은 것

- 실제 화면에서 카드 모양, 스크롤바 간격, 좁은 위젯 칸의 `+N` 가독성 확인.
- 한 프로젝트·하루에 기록이 50개를 넘는 경우의 쪽 넘김은 없다.
