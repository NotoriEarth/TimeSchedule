# Windows 스타일 연·월 선택

2026-10-31, 기존 PR #6의 후속 UI 변경이다. 위젯과 다이어리에 같은 선택창을 사용한다.

## 사용 방법

- 달력의 **년** 클릭: 4열 연도 격자를 연다. 상단 화살표로 이전/다음10년을 보고, 연도를 선택하면 월 선택으로 넘어간다.
- 달력의 **월** 클릭: 해당 연도의1~12월 격자를 바로 연다. **월을 클릭하면 그 연·월로 이동하고 창이 닫힌다.**
- 월 선택 화면 상단의 연도를 누르면 다시 연도 선택으로 돌아간다. 이 화면의 화살표는1년씩 바꾼다.
- 선택된 연도/월은 테마 강조색으로 채운 사각형으로 표시한다. 앞뒤 연대는 흐리게 표시하며 지원 범위 밖은 선택할 수 없다.
- 둘러보기·연도 선택만으로 원본 달력은 바뀌지 않는다. **취소/Esc**로 닫으면 그대로다. 직접 날짜를 입력하려면 아래 **날짜 직접 입력**을 펼쳐 `YYYY-MM-DD`를 입력하고 이동 또는 Enter를 누른다.
- 원본 위젯/다이어리 중앙 배치, 두 달력의 독립된 날짜, 기존 일정 초안, 공통 일정 편집 폼을 유지한다.

첨부된 Windows 화면의 격자·계층 선택 방식을 Rust/Iced로 구현했으며 앱의 다크/라이트 색상을 사용한다. 새 런타임·의존성·DB 변경은 없다. 기본360×420, 최소320×400 논리 픽셀이다.

## 검증

- `cargo test --workspace --locked --offline`: **95개 통과, 의도된 제외2개**.
- 실제 Iced 렌더러에서16개 연도와12개 월을 확인하고 `2028 → 2월` 클릭을 보내 두 원본 달력의 이동과 다른 달력·초안 보존을 검증했다.
- 10년/1년 이동, 인접 연대 선택, 취소/Esc, 1900/9998경계, 잘못된 날짜와 윤년 입력을 확인했다.
- 최소 창에서 연도/월 격자와 확장된 날짜 입력·오류 메시지의 모든 레이아웃 요소가 창 안에 들어가는지 검사했다.
- 다크·라이트 연도/월, 마지막 연도 범위, 좁은 직접 입력의 PNG6개를 실제 렌더러로 생성·확인했다. PNG는 Windows 바탕화면 캡처가 아니다.
- 독립 코드 검토 후, 기존 다이어리 월 화살표가 지원 범위를 넘어간 상태에서 선택창을 여는 경로를 재현하고 수정했다. 선택창 초기 연도와 월 선택 결과를1900~9998로 제한한다.

실제 Windows 포커스, 마우스/Enter 전달, 원본 창 이동 후 배치, 서로 다른 DPI의 모니터 전환은 사용자 확인 항목이다. 기존 native 위치 검증과 렌더러 테스트가 실제 사용자 조작 성공을 의미하지는 않는다.

## 직접 확인

1. 기존 앱을 트레이에서 완전히 종료하고 아래 최신 실행 파일을 실행한다.
2. 위젯과 다이어리에서 각각 년/월을 눌러 시작 화면이 맞는지 확인한다.
3. 화살표로10년을 이동하고 연도→월을 선택해 이동한다. 월 선택 화면의 연도 제목을 눌러 돌아가기도 확인한다.
4. 여러 연도를 둘러본 뒤 취소/Esc를 눌러 원래 달력이 유지되는지 확인한다.
5. 날짜 직접 입력에서 `2028-02-29`는 이동하고 `2027-02-29`는 오류로 남는지 확인한다.
6. 다크/라이트 전환, 좁은 창, 위젯/다이어리의 다른 위치에서 선택창 표시를 확인한다.

빌드/테스트 로그와 PNG는 로컬 `artifacts/calendar-picker/`에 있다. 실행 파일과 테스트 데이터는 Git에 포함하지 않는다. 사용자 테스트 후 명시적인 승인 전까지 머지하지 않는다.
