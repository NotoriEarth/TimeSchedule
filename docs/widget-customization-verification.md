# 바탕화면 위젯 크기·표시 기간·디자인·연월 이동

후속 수정과 최신 실행 파일은 [다이어리·팝업·공통 폼 검증](diary-navigation-verification.md)을 참고한다.

2026-10-31, `codex/widget-customization`. 기반은 우선 기능 PR #5의 `3307e0c`이며, 이 PR 위에 쌓는 변경이다. Rust/Iced 네이티브 앱에 적용한다.

## 적용 내용

- **크기**: 잠금을 풀고 오른쪽 아래 손잡이를 끌거나, 위젯의 **설정 → 크기와 표시 기간**에서 가로·세로를 입력한다. 입력 범위는 논리 픽셀 기준 가로 320~3840, 세로 220~2160이다. 잠금은 크기와 이동을 막으며 일정 편집·완료 체크는 유지한다. 크기 변경 후 즉시 잠그거나 종료해도 마지막 값의 저장을 기다린다.
- **표시 기간**: 기본 월간 보기는 해당 월 전체를 4~6주로 표시한다. 기간 보기는 2~8주, 지난주 포함은 0~2주(전체 주 수 미만)를 선택한다. 기간 보기의 화살표는 한 주, 월간 보기의 화살표는 한 달 이동한다. 과거·미래를 탐색 중에는 날짜가 바뀌어도 오늘로 돌아가지 않는다. **오늘**을 누르면 오늘을 따라간다.
- **글꼴·간격**: 설치된 글꼴, 날짜/일정 글자 크기, 셀 사이·안쪽 여백, 일정 줄 간격을 조절한다. 촘촘하게/기본/여유롭게 프리셋과 초기화를 제공한다. 선택한 글꼴이 없으면 기본 글꼴로 표시한다. 큰 글꼴·넓은 여백으로 좁은 창에 날짜가 들어가지 않으면 달력 영역을 가로로 스크롤할 수 있다. 세로 공간이 부족하면 세로 스크롤을 제공하며 손잡이는 창 모서리에 유지한다.
- **색상**: 배경·글자·오늘 강조·일요일·토요일·테두리를 선택하고 `#RRGGBB` 값을 입력해 **적용**한다. 다크/라이트 설정은 따로 저장하며 주말색은 일정 분류색에 영향을 주지 않는다. 기존 배경 전용 투명도를 유지한다.
- **연·월 이동**: 상단 `2025년`이나 `9월`을 누르면 두 값이 함께 있는 작은 창이 열린다. 누른 항목의 입력칸에 포커스와 전체 선택을 요청한다. 두 값을 바꾸고 **이 월로 이동** 또는 Enter로 적용한다. 날짜 직접 입력도 지원한다. 취소·Esc·창 닫기는 화면을 이동시키지 않으며 작성 중인 일정 초안을 보존한다. 이동 범위는 1900~9998년이다.

일정 DB 구조는 변경하지 않는다. 기존 `preferences.json`에는 기본 설정을 채우며 새 설정도 같은 파일에 저장한다. 외형 변경은 일정 DB를 다시 조회하지 않는다. 날짜 조회와 렌더링은 하나의 표시 범위 계산 결과를 공유한다.

| 독립 코드 리뷰 | 크기 조정 시작에 필요한 창 스타일, 잠금 직전 크기 보존, 주말/일정 색상 분리, 큰 글꼴 월 경계 표시를 보완하고 회귀 테스트 통과 |

기존 `WS_CHILD` 연결을 보존하면서 네이티브 위젯에만 `WS_THICKFRAME`을 유지하고, `WM_NCCALCSIZE` 처리로 테두리 없는 전체 client 영역을 유지한다. 근거: [Microsoft WM_NCCALCSIZE 문서](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-nccalcsize). winit의 최상위 창 스타일 변경 함수는 호출하지 않는다.

연속 PNG 생성 중 테스트 프로세스의 모든 스레드가 Windows에서 `Suspended` 상태인 것을 확인했다. 생성기를 화면 이름별로 나눠 실행하여 19개를 모두 생성했다. 앱 내부 교착으로 확인된 현상은 아니다.

PNG는 실제 Iced 렌더러 출력이며 **Windows 바탕화면 캡처는 아니다**. 새 EXE에 대해서도 창 캡처가 시간 초과했다. 블라인드 클릭은 수행하지 않았다. 실제 손잡이 드래그, OS 포커스·전체 선택·IME, 여러 모니터/DPI 이동과 바탕화면 합성은 사용자 확인 항목이다. 네이티브 fixture는 실제 마우스 드래그의 성공을 입증하지 않는다.

메모리·CPU 벤치마크는 이번 변경에서 다시 수행하지 않았다. 기존 실행 중인 사용자 앱은 종료하거나 교체하지 않았다.

## 직접 테스트

1. 기존 네이티브 앱을 트레이에서 완전히 종료하고 `artifacts/TimeSchedule-widget-customization.exe`를 실행한다.
2. 상단의 **년**을 눌러 해당 연도가 선택되는지 확인하고 값을 바꾼다. **월**에서도 반복한다. 다른 항목은 그대로 유지되는지, 취소하면 이동하지 않는지 확인한다.
3. 날짜 직접 입력으로 윤년의 `2028-02-29`에 이동한다. `2027-02-29`는 오류를 표시하고 이동하지 않아야 한다.
4. 잠금을 풀고 오른쪽 아래 손잡이로 크기를 바꾼 뒤 바로 잠그고 종료·재실행한다. 크기가 보존되는지 확인한다. 숫자로 크기 적용도 확인한다.
5. 설정에서 기간 보기 4주/지난주 0주와 5주/지난주 1주를 비교한다. 과거로 이동해도 표시 범위가 임의로 오늘로 돌아가지 않아야 한다.
6. 글꼴·글자 크기·간격 프리셋을 바꾸고 작은 창에서도 날짜와 제어 버튼에 접근할 수 있는지 확인한다. 큰 설정에서는 스크롤이 생길 수 있다.
7. 다크 모드의 토요일 색을 바꾸고 밝은 모드 색상이 유지되는지 확인한다. 평일의 파란 일정 표식은 바뀌지 않아야 한다.
8. 기존 기능인 날짜 더블클릭 편집·완료 체크·한글 입력·미저장 확인·위젯 이동·배경 투명도도 확인한다.

```powershell
$env:TIMESCHEDULE_DATA_DIR = 'C:\LSH\TimeSchedule\.test-data\widget-customization-user'
& 'C:\LSH\TimeSchedule\artifacts\TimeSchedule-widget-customization.exe'
```

빌드/테스트 로그와 미리보기는 로컬 `artifacts/widget-customization/`에 있다. 실행 파일과 테스트 데이터는 Git에 포함하지 않는다. 사용자 확인 후 명시적인 승인을 받기 전에는 머지하지 않는다.
