# 0.8.0 작업 종료·오프라인 기록 후속 검증

사용자 요청에 따라 별도 오전 9시 자동화 `timeschedule`을 PAUSED로 전환했다. 작업 종료마다 다이어리에 전체 원문을 먼저 남기고, 앱 실행 중 대기 기록만 자동 재시도한다. 연결 후에는 원문을 유지하면서 같은 항목에 검증된 Space 링크를 붙인다.

## 2026-11-01 PR #8 재검증

사용자의 선행 테스트 요청으로 PR #8과 로컬 HEAD `bd8431bc6f6137ce3042a8ca59cb02110e74183c`의 일치 및 깨끗한 작업 트리를 확인하고 재검증했다. 기존 136개 테스트는 통과했지만 실제 대기 기록에서 기존 테스트가 다루지 않은 목록 블록의 비교 문제가 발견됐다.

Space는 연속된 목록 항목을 각각 Markdown 블록으로 반환했다. 검증기가 모든 블록 사이에 빈 줄을 붙여 다시 구성하면서 원문의 한 줄 간격 목록을 불일치로 판정했다. 실제 기록의 단어·수치·링크는 같았다. 목록 항목별 블록 반환을 재현하는 테스트의 실패를 확인한 뒤, 인접한 단일 행 목록 블록 사이의 구분자만 원문에 맞춰 검증하도록 수정했다. 일반 문단 구분, 코드 내부 공백, 단어·수치·링크·순서 변경은 계속 거부한다. 원문 파일과 다이어리 본문은 재작성하지 않는다.

최종 자동 테스트는 **138개 통과**(Rust workspace 114, Node 20, Tauri 4), 기존 의도적 제외 2개다. `cargo fmt --all --check`, `git diff --check`와 `scripts/build-native.ps1 -Offline`도 통과했다. 네이티브 코드는 바뀌지 않아 대표 EXE의 버전·크기·해시는 아래 0.8.0 정보와 같다. 이번 수정은 저장소의 외부 전달 스크립트에 적용됐다.

실제 브랜치 정리 기록을 수동 재시도해 [기존 Space 페이지](https://chatgpt.com/space/page_ff34e87b81fc81918c13204354ecb9e0)를 다시 읽고 `complete`까지 확인했다. 페이지 ID를 유지했으며 사용자 DB의 해당 source_ref만 읽어 기록 1개, 전체 원문 포함, 연결 완료 표시와 정확한 URL을 확인했다. 이 회차는 수동 재시도이며 앱 자동 재시도에 대한 이전 검증과 구분한다.

대표 EXE와 동일한 복사본을 별도 테스트 DB로 실행했다. 링크 없는 원문 저장 → 실행 중 `queued` → 앱의 inbox 처리 → 동일 entry ID에 링크 연결을 확인했다. 같은 입력을 다시 보내도 기록은 1개였고 본문은 같았다. 테스트 DB에서 수동 편집과 삭제를 각각 재현한 후 더 높은 revision을 보냈을 때 `conflict`로 보존되는 것도 확인했다. 이번에 실행한 격리 테스트 프로세스만 종료했다.

실제 Windows 창은 확인했으나 Computer Use 캡처가 `FrameArrived timed out`과 `window capture timed out`으로 두 번 실패했다. 따라서 마우스 클릭·한글 IME 조합·링크 클릭 후 브라우저 이동의 육안 확인은 완료로 표시하지 않는다. PR #8은 테스트 후에도 사용자 승인 전까지 미병합 상태를 유지한다.

## 실제 연결 실패와 자동 복구

이번 작업의 실제 원문을 사용했다. 명시적으로 없는 Codex 경로를 지정해 연결 실패를 재현했고, 사용자 다이어리의 기존 항목 하나에 전체 원문과 `Space 연결 대기`가 저장됐다. 미검증 링크는 빈 값이었다. 전달 상태는 `waiting_space`, `localSaved=true`였다.

최종 대표 EXE를 정상 사용자 계정으로 실행했다. 앱이 20:35:56(KST)에 대기 전송을 자동 시작했고, 실제 Luna/Pages 저장·다시 읽기 검증이 통과했다. 20:36:56에 GUI inbox가 링크 전달을 저장하고 목록을 갱신했으며 20:36:57에 전달 상태가 `complete`가 됐다. 이 복구 구간에는 수동 sync를 실행하지 않았다. 같은 항목의 원문을 보존하고 [기존 Space 페이지](https://chatgpt.com/space/page_fdbfca54dc988191a30560abf42934d6)에 연결했다.

최종 작업 요약인 source revision 4도 앱 재시도로 완료됐다. 중간의 Windows 상태 파일 교체 EPERM 오류 후 원문을 잃지 않고 다음 자동 재시도가 이어졌다. 20:44:12에 complete·오류 없음이 확인됐고, DB에서 동일 entry ID의 항목 1개·전체 원문 일치·Space 연결 완료·기존 페이지 URL을 확인했다. 진단용 수동 재시도는 앱이 보유한 잠금으로 거절되어 전송에 개입하지 않았다.
