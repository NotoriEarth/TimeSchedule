대표 실행 파일은 **`artifacts/TimeSchedule.exe`** 하나입니다. Rust/Iced로 화면을 만들며 실행에 WebView/JavaScript 런타임이 필요하지 않습니다. 앱 설정·창 제목과 Windows 파일 속성에서 버전을 확인할 수 있습니다. [버전 규칙과 업데이트 이력](CHANGELOG.md)을 참고하세요.

[0.8.0 자동 기록 안내](docs/project-records.md)와 [최신 검증 결과](docs/offline-project-records-verification.md)를 참고하세요. [초기 0.8.0 검증](docs/project-records-verification.md)과 [0.7.0 검증](docs/release-0.7.0-verification.md)도 보존합니다.

```powershell
.\scripts\build-native.ps1
.\artifacts\TimeSchedule.exe
```

네이티브 기본 저장 폴더는 `%LOCALAPPDATA%\com.timeschedule.personal.native-experiment`, 파일은 `schedule.db`입니다. 기존 앱의 DB를 자동으로 가져오지 않습니다. `TIMESCHEDULE_DATA_DIR`로 별도 테스트 폴더를 지정할 수 있습니다. 기존 DB의 호환성 확인에는 원본 대신 일관되게 백업한 복사본을 사용하세요.

PR #2–#6의 Rust 이식·테마·위젯·편집·설정·연월 선택 변경은 사용자 승인 후 main에 병합했습니다. 기존 Tauri/Svelte 소스와 빌드 경로도 보존합니다. 두 앱은 공통 SQLite/Git 코어를 사용합니다.

최신 앱에는 날짜 더블클릭 편집, 완료 체크, 배경 전용 투명도, 크기·표시 주 수·글꼴·색상 설정, Windows식 연도→월 선택, 위젯과 다이어리 공통 일정 폼이 포함됩니다.

0.8.0은 Codex 작업 종료 시 다이어리에 개발 기록 원문을 먼저 보관하고 Space에 연결합니다. 연결 실패 중에도 기록을 남기며, 앱 실행 중 누적된 대기 기록만 재시도해 복구 후 같은 항목에 링크를 붙입니다. 별도 오전 9시 포트폴리오 자동화는 중지했습니다. Space 내용은 PR 작성에 유용할 때만 재사용합니다. 기록용 CLI는 GPT-6 Luna medium과 원문 검증을 사용합니다. 사용자 편집을 보존하고 편집 중에는 외부 기록 수신을 미룹니다. 외부 전달에는 Node.js와 로그인된 Codex CLI·Pages 연결이 필요합니다.

기존 수동 테스트 EXE는 `artifacts/archive/`에 보관합니다. 앞으로 빌드할 때도 `TimeSchedule.exe`를 교체하고 이전 파일은 보관하므로 실행할 파일 이름은 늘어나지 않습니다. 실행 중이면 저장 후 트레이에서 완전히 종료하고 빌드하세요. 빌드나 버전 검증 실패 시 기존 EXE를 교체하지 않습니다. 의존성이 준비된 환경에서는 `scripts/build-native.ps1 -Offline`을 사용할 수 있습니다.

## 기존 Tauri 앱


오늘의 일정과 작은 할 일을 정리하는 Windows용 개인 달력 프로토타입입니다. Tauri 2, Svelte 5, TypeScript, Rust, SQLite로 구성하며, 계정이나 서버 없이 내 컴퓨터에 데이터를 저장합니다.

2026-10-29 다이어리 개발 브랜치에서는 **상세 창을 주 화면인 만년 다이어리**로 구성했습니다. 월간 달력의 일요일 앞 주간 버튼은 그 다음 월요일부터 다음 일요일까지 열며, **월간으로** 버튼으로 원래 보던 월에 돌아옵니다. 날짜를 누르면 해당 날짜의 일정 편집창이 열립니다. 주간 기록은 제목을 펼쳐 본문과 출처를 보고, 필요한 만큼 추가할 수 있습니다.

프로젝트별 자유 노트·트러블슈팅·개발 기록, 로컬 Git 커밋 가져오기, 편집 가능한 근거 요약과 포트폴리오 초안을 제공합니다. Git은 프로젝트의 저장소 경로에서 **Git 커밋 수집**을 눌러 최근 500개를 가져옵니다. 재수집은 기존 기록과 사용자가 수정한 내용을 보존합니다. 요약은 저장된 자료를 정리한 **로컬 초안**이며 외부 AI 분석 결과가 아닙니다. ChatGPT 공부 내역·Space 연동, 자동 수집 주기, 기기 간 동기화는 아직 연결하지 않았습니다.

전체 검색은 일정·할 일·메모·프로젝트·개발 기록의 제목과 본문을 찾습니다. SQLite FTS5 인덱스(3글자 이상), 짧은 검색어의 문자 검색, 최대 50개 결과와 입력 대기를 사용합니다. 기록 목록은 200개씩 불러오고 본문은 펼칠 때 읽습니다. 이 변경의 메모리 절감량은 아직 측정하지 않았으며 아래 과거 수치와 구분해야 합니다. 당시 테스트 실행 파일은 보관 폴더로 이동했습니다. [직접 확인할 절차](docs/diary-verification.md)를 참고하세요.

현재 사용할 수 있는 기능은 다음과 같습니다.

- 한국어 월간 달력, 오늘 강조 표시, 선택한 날짜의 일정 목록
- 일정 추가·수정·삭제, 하루 종일 또는 시작·종료 시간, 색상, 메모, 완료 표시
- 날짜를 지정할 수 있는 할 일과 별도의 메모 관리
- 날짜 칸마다 일정이 보이는 넓은 바탕화면 월간 달력과 오늘 일정 요약
- 상단의 **이동하기 / 위치 고정**, 넓은 제목 영역을 끌어 위치 이동
- **불투명도 40~100% 조절**과 설정 저장 (기본 82%)
- 위젯에서 날짜를 눌러 관리 창 열기, 저장 후 두 창의 데이터 갱신
- 트레이에서 관리 창 열기, 위젯 표시·숨기기, 완전 종료

관리 창의 닫기 버튼은 앱을 완전히 종료하지 않습니다. 관리 창과 그 WebView를 해제하고 트레이에 남으며, 다시 열면 저장된 데이터를 불러옵니다. 앱을 끝내려면 트레이 메뉴의 **완전 종료**를 선택하세요.

0.1.2에서는 실행 중 해상도·배율이 바뀌거나 모니터가 분리되어 위젯이 화면 밖으로 나가면, 위젯의 위치와 크기를 현재 모니터 작업 영역 안으로 자동 보정합니다. 위치 고정 상태에서도 보정하며 잠금과 불투명도는 유지합니다. 드래그 중에는 개입하지 않고, 창의 메시지 처리가 가능한 상태에서 약 1초 간격으로 검사합니다. 버튼에 접근할 수 없으면 관리 창의 **위젯 위치 복구** 또는 트레이의 **바탕화면 달력 위치 복구**를 사용하세요. 자동 보정은 기존 창을 화면 안에 맞추며 Explorer 재시작으로 파괴된 창을 자동 재생성하는 기능은 아닙니다.

0.1.1에서는 작은 카드 대신 최대 900×560 논리 픽셀의 월간 달력을 표시합니다. 화면이 작으면 자동으로 줄이고, 기존 위치가 화면 밖으로 나가면 안쪽으로 보정합니다. **이동하기**를 누른 뒤 상단 제목 또는 안내 영역을 끌고, 배치를 마치면 **위치 고정**을 누르세요. 이미 **위치 고정** 버튼이 보이면 이동할 수 있는 상태입니다. 하단의 **불투명도**를 낮출수록 바탕화면 배경이 더 비칩니다. 현재는 창 전체를 반투명하게 처리하므로 글자도 함께 조금 옅어집니다. 배경만 투명하게 하거나 흐리게 만드는 방식은 아닙니다.

바탕화면 위젯은 Windows 10의 Explorer 바탕화면 호스트에 연결하는 실험 기능입니다. 일반 창을 최소화해도 바탕화면에 남고 다른 앱보다 앞에 뜨지 않는 동작을 목표로 합니다. 연결 상태를 앱에 표시하며, 지원하지 않는 환경에서는 연결 실패를 알립니다. 2026-10-28 현재 PC에서 0.1.0의 관리자 창과 Win+D 이후 달력 표시, 0.1.1 수정본의 배경 비침과 상단 드래그 이동을 사용자가 확인했습니다. 0.1.2 적용 후에는 가려졌던 위젯 제어 버튼이 다시 보이는 것을 사용자가 확인했습니다. Windows 11 및 다른 Explorer 구성에서의 동작은 별도 확인이 필요합니다.

이 저장소에는 소스와 빌드 방법을 포함합니다. 실행 파일과 개인 데이터는 Git으로 관리하지 않습니다. 아래 Tauri 빌드 결과는 `src-tauri/target/release/timeschedule.exe`입니다. 대표 네이티브 EXE와 구분해 사용하세요. 2026-10-28의 0.1.2 빌드 크기는 7,607,296바이트(7.25MiB)입니다. 실행 환경에는 Microsoft Edge WebView2 Runtime이 필요합니다. Rust, Cargo, Microsoft C++ Build Tools는 소스 빌드에 사용하는 도구이며, 사용자가 실행 파일을 실행하기 위해 함께 배포하는 앱 구성 요소가 아닙니다. 현재는 앱을 한 번만 실행하세요. 중복 실행 방지는 아직 포함하지 않습니다.

소스에서 실행하거나 빌드할 때는 프로젝트 루트의 PowerShell에서 아래 명령을 사용합니다. Node.js와 npm이 필요하며, 먼저 프런트엔드 의존성을 설치합니다.

```powershell
npm.cmd ci
```

이 작업 공간의 Rust 및 C++ 빌드 도구는 `.tooling`에 구성되어 있습니다. `scripts/toolchain.ps1`은 현재 PowerShell 세션에 해당 도구의 환경 변수를 설정합니다. 새 작업 공간에서 도구를 준비할 때는 `scripts/install-rust.ps1`, `scripts/install-buildtools.ps1`을 참고하세요. `.tooling`은 컴파일러와 빌드 의존성 보관 폴더이며, 앱의 실행 시 메모리 사용량이나 배포 크기를 의미하지 않습니다.

네이티브 개발 모드로 실행하려면:

```powershell
. .\scripts\toolchain.ps1
npm.cmd run tauri dev
```

릴리스 빌드는 다음과 같습니다. `build.ps1`은 프런트엔드 타입 검사와 프런트엔드·네이티브 빌드를 실행합니다. 설치 프로그램은 만들지 않으며 대표 네이티브 EXE를 덮어쓰지 않습니다.

```powershell
.\scripts\build.ps1
.\src-tauri\target\release\timeschedule.exe
```

디버그 빌드는 `scripts/build.ps1 -DebugBuild`를 사용합니다. 이때 원본 실행 파일은 `src-tauri/target/debug/timeschedule.exe`에 생성됩니다.

기존 Tauri 앱의 기본 저장 위치는 Tauri의 `app_data_dir()`이 반환하는 `com.timeschedule.personal` 앱 데이터 폴더입니다. Windows에서는 보통 `%APPDATA%\com.timeschedule.personal`이며, 앱의 **내 컴퓨터에 저장** 정보에서 실제 경로를 확인할 수 있습니다.

| 파일 | 내용 |
| --- | --- |
| `schedule.db` | 일정, 할 일, 메모를 저장하는 SQLite 데이터베이스 |
| `preferences.json` | 위젯 위치, 위치 잠금, 표시 설정 |
| `prototype.log` | 바탕화면 연결 및 오류 진단 기록 |

앱 실행 중에는 SQLite 보조 파일인 `schedule.db-wal`, `schedule.db-shm`이 함께 생길 수 있습니다. 백업하려면 트레이에서 완전 종료한 뒤 저장 폴더를 복사하세요.

테스트 데이터를 별도 폴더에 저장하려면 실행 전에 `TIMESCHEDULE_DATA_DIR`을 지정합니다. 앱이 지정한 폴더를 생성하고 사용합니다.

```powershell
$env:TIMESCHEDULE_DATA_DIR = Join-Path $PWD '.test-data'
.\src-tauri\target\release\timeschedule.exe
```

다음 실행부터 기본 저장 위치로 돌아가려면 앱을 완전히 종료한 후 같은 PowerShell에서 `$env:TIMESCHEDULE_DATA_DIR = $null`로 지웁니다.

브라우저에서 화면만 확인하려면 `npm.cmd run dev`를 실행하고 `http://127.0.0.1:1420`을 엽니다. 브라우저 미리보기는 해당 브라우저의 **localStorage**에 저장합니다. 네이티브 앱의 **SQLite와 데이터를 공유하거나 동기화하지 않으며**, 브라우저의 위젯 미리보기도 실제 바탕화면 연결 기능을 제공하지 않습니다.

자동화 도구가 이 PC의 네이티브 창 캡처와 좌표 클릭을 수행하지 못해 마지막 행은 검증 완료로 표시하지 않습니다. 표시·반투명·이동 여부는 사용자의 직접 확인을 근거로 기록했습니다. 관리자 화면의 접근성 트리와 기본 데이터 로드는 확인했으며, 브라우저 미리보기에서는 일정 생성·저장과 새 위젯의 월 이동·불투명도 조절을 확인했습니다. [새 달력 미리보기](docs/images/desktop-calendar-preview.png)는 브라우저 화면으로 실제 바탕화면 캡처가 아닙니다.

아래 표는 빈 데이터로 실행한 Windows 10 Pro 22H2, 화면 배율 200% 환경의 메모리 측정입니다. 앱 본체와 그 WebView2 자식 프로세스를 모두 포함합니다. 버전과 열린 창 상태를 구분해 읽어야 합니다.

| 버전·실행 상태 | 전용 상주 메모리 합계 | 전체 작업 집합 합계 | 전용 커밋 합계 |
| --- | ---: | ---: | ---: |
| 0.1.0 관리자와 작은 위젯 | 121.10MiB | 426.91MiB | 248.28MiB |
| 0.1.0 작은 위젯만 유지 | 97.85MiB | 363.71MiB | 212.55MiB |
| 0.1.1 관리자와 넓은 반투명 달력 | 124.91MiB | 424.71MiB | 362.49MiB |

0.1.1 측정 원본은 로컬 전용 파일 `artifacts/memory-0.1.1-manager-and-widget.json`이며 저장소에 포함하지 않습니다. 넓은 반투명 창으로 바꾸면서 전용 커밋이 늘었으며, 0.1.1의 위젯 단독 상태는 아직 별도 측정하지 않았습니다.

전체 작업 집합 합계는 공유 페이지를 중복 계산하므로 앱만의 실제 추가 메모리와 같지 않습니다. 전용 커밋도 현재 RAM 상주량과 다릅니다. 수치는 이 PC에서 한 번 측정한 기준점이며, OS·WebView2 버전·일정 개수에 따라 달라집니다. 작은 실행 파일 크기만으로 메모리 최적화가 끝났다고 판단하지 않습니다. 0.1.0 원본 결과도 로컬 전용 파일 `artifacts/memory-manager-and-widget.json`, `artifacts/memory-widget-only.json`에 있으며 저장소에 포함하지 않습니다. 실행 중인 앱의 프로세스 ID를 지정해 다시 측정할 수 있습니다.

```powershell
.\scripts\measure-memory.ps1 -AppProcessId <TimeSchedule의_프로세스_ID> -ExpectedExecutablePath <실행한_EXE의_절대경로>
```

저장소 테스트는 재실행 후 데이터 유지, 날짜 범위의 양 끝 포함, 잘못된 날짜·시간·색상 거부, 일정·할 일·메모 수정과 삭제, 실패한 수정의 기존 데이터 보존 등을 확인합니다. 직접 검사하려면:
